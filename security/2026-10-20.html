Apache Camel 4.18.5 / 4.22.1 - デシリアライズによる任意コード実行 CVSS 10.0 を含む38件を一括公開Critical

識別子CVE-2026-78162（CVSSv4.0 10.0）、CVE-2026-88900 / 78165 / 83531（8.8）、CVE-2026-88901 / 80344 / 80343 / 80312 / 78164（8.2）ほか計38件
影響Apache Camel 4.0.0〜4.18.5 未満、4.19.0〜4.22.1 未満（Java統合フレームワーク。各コンポーネントに跨る）
公開NVD登録 2026-10-19 10:17〜11:17 UTC（JST 2026-10-19 19:17〜20:17）
  • 最も深刻なのは camel-hazelcast の脆弱性（CVE-2026-78162、CVSSv4.0 10.0）ですわ。同コンポーネントが自らの構成からインスタンスを生成する際、既定の JavaSerializationFilterConfig を適用しておらず、Javaネイティブのデシリアライズを経由した任意コード実行に到達しうる問題です。
  • CVE-2026-78165 は camel-spring-redis で、serializer オプションが未指定のとき素の JdkSerializationRedisSerializer が遅延生成されてしまう問題（8.8）。CVE-2026-88900 は camel-jgroups の createExchange(Message)、CVE-2026-83531 は式言語インジェクションで、いずれも8.8です。
  • このほか、リモートファイル消費系のパストラバーサル4件（FTP・SFTP・SMB・Azure Files、各7.4）、OAuthコンポーネントの認証スキップ（8.2）と state 欠如によるCSRF（6.1）、Netty HTTP のセキュリティ制約がパス大文字小文字を区別していた問題（8.2）、AS2の非同期MDN要求によるSSRF（8.2）、XXE（8.2）、Shiroの資格情報検証スキップ（5.9）、Tika・Mail・MLLPへのヘッダ／秘匿情報の流出などがまとめて修正されています。
  • Camelは業務統合のハブになりがちで、経路上の秘匿情報がそのまま外部へ流れる種類の不備が混在しております。とくに外部と通信するコンポーネント（HTTP系、FTP/SMB系、OAuth、AS2）をご利用でしたら、4.18.5 または 4.22.1 以降への更新を優先なさってくださいませ。

Apache Answer 2.0.3未満 - 反応APIの可視性制御欠如（CVSS 9.8）を含む13件Critical

識別子CVE-2026-90910（9.8）、CVE-2026-86589、CVE-2026-79633、CVE-2026-79624、CVE-2026-79620、CVE-2026-79613、CVE-2026-76994、CVE-2026-71563、CVE-2026-68482、CVE-2026-67249、CVE-2026-64945、CVE-2026-64944、CVE-2026-64943（計13件）
影響Apache Answer 2.0.2 以下（Java／Spring Boot ベースのQ&Aプラットフォーム。修正版は 2.0.3）
公開NVD登録 2026-10-19 10:16 UTC（JST 2026-10-19 19:16）
  • CVE-2026-90910（9.8）は、リアクションAPIがコンテンツの可視性制御を実施していない問題です。非公開コンテンツに紐づくリアクションのメタデータを権限のない利用者が読み取れるほか、自分自身のリアクションを追加・削除できてしまいます（CWE-306）。
  • 同製品では、MCPの回答取得ツールがグローバルAPIキー保持者に対して非公開・削除済み・審査中の回答本文へのアクセスを許す問題、非公開質問に紐づく招待ユーザー一覧の可視性チェック欠如、類似質問検索の認可不備、hide/show 操作が誤った権限（hide ではなく unpin）で判定される問題も確認されています。
  • さらに、セッション失効が不完全で、失効した利用者が古い visit トークンのまま非公開のアップロードファイルへ到達できる問題、メール用の検証コードが用途を区別せず別フローの認証に流用できる問題、外部IDを欠いた外部ユーザーセッションが生成され以降のリクエストで本人確認を回避できる問題、APIキーが全認証リクエストでログへ平文記録される問題も含まれます。
  • 社内ナレッジやサポートポータルとしてApache Answerをお使いの場合は、2.0.3へ更新のうえ、公開済みのAPIキーの失効とログの取り扱いも併せてご確認くださいませ。
