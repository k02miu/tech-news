1. pnpm 連続セキュリティアドバイザリ（6件）— ロックファイル由来の任意コード実行・パストラバーサル・bin 削除攻撃、--ignore-scripts でも成立 CRITICAL

CVE／GHSACVE-2026-55698（CVSS 3.1: 8.1 AV:N/AC:L/PR:N/UI:R/S:U/C:H/I:H/A:H）／CVE-2026-55700（CVSS 7.3 パストラバーサル）／CVE-2026-55699（PNPM_HOME 削除、A:H）／GHSA-fr4h-3cph-29xv／GHSA-72r4-9c5j-mj57／GHSA-qrv3-253h-g69c（CVE未割当、High）

  • 概要 — npm 互換の高速パッケージマネージャ pnpm に対し、2026-06-26〜27 に6件の High/Critical 級アドバイザリが連続公開された。全て pnpm-lock.yaml に細工された値を仕込んだ悪意ある／汚染されたリポジトリをユーザーが pnpm install することで成立し、--ignore-scripts を指定しても lifecycle script に依存せず発火する点が共通。
  • CVE-2026-55698（CRITICAL 相当）env lockfile 由来の package-manager 切替で攻撃者選択バイナリ実行 — pnpm は pnpm-lock.yaml の第1 YAML ドキュメントに package-manager ブートストラップメタデータを保持可能。修正前はコミット済み env lockfile に合致する pnpm／@pnpm/exe バージョンが存在する場合、鮮度解決をバイパスし、ロックファイルが選んだ bytes を自動バージョン切替時にインストール・実行しうる。悪意あるリポジトリは packageManagerDependencies records/snapshots をコミットし、fresh package-manager resolution を迂回して pnpm 自体を乗っ取ることが可能。CI での自動 pnpm install が実行コンテキストに乗るためシークレット窃取起点になる
  • CVE-2026-55700（HIGH）stage download のパストラバーサルで任意上書き — pnpm stage download がレジストリ由来の package name/version からローカル filename を派生し、細工された manifest でダウンロード先ディレクトリを越えて別ファイルを上書き可能。修正版は name/version を検証し実パスを検証後に書き込み
  • CVE-2026-55699（HIGH）bin 名パストラバーサルで PNPM_HOME 削除 — manifest bin object のキーとして ""／.／.. が bin-name guard をすり抜け、悪意あるパッケージを global install した後に remove/update/add-replacement で path.join(globalBinDir, ".")／".." が removeBin に渡り global bin dir やその親（PNPM_HOME 等）が削除される
  • GHSA-fr4h-3cph-29xv（High）hoisted install の alias → node_modules 外インポート — 細工された lockfile alias が hoisted node_modules 直下に結合され、traversal alias はディレクトリを脱出、.bin／.pnpm 等の予約 alias は pnpm 所有レイアウトを上書きしうる。pacquet (Rust) 側にも影響
  • GHSA-72r4-9c5j-mj57（High）patch-remove の任意ファイル削除 — 細工された patch entry が patches ディレクトリ外に解決し、pnpm patch-remove が任意の到達可能ファイルを削除しうる。シンボリックリンク／dangling victim の再現も報告
  • GHSA-qrv3-253h-g69c（High）configDependencies 由来のシンボリックリンク書き出し — env lockfile の configDependencies package name をそのまま node_modules/.pnpm-config/ 下のシンボリックリンク作成に使用。traversal-shaped 名（../../PWNED_CFGDEP）でプロジェクト外に symlink を作成。--ignore-scripts でも発火
  • 被害シナリオ — Next.js / React / Hono / Node.js 系スタックで pnpm を採用し、CI で pnpm install を実行する全環境が対象。DER依存・PR 由来の fork-build・CodeSandbox 的な sandbox・生成 AI agent の一時 checkout（OpenClaw・Claude Code・Hermes Agent 等のエージェントが外部リポジトリを pnpm install する運用）でも credential 窃取や ホスト汚染に直結しうる
  • 対応 — pnpm を 10.34.2／11.5.3（可能なら 11.7.0）以降に即時更新。CI 上で pnpm install が実行される全 workflow で pnpm バージョンを pinning し、lockfile の差分（特に packageManagerDependencies・configDependencies・hoisted aliases・patchedDependencies）を PR review で精査。信頼できない PR 由来の pnpm-lock.yaml を CI で再現せず --frozen-lockfile／ pnpm install --prod の検証も活用。pacquet 利用環境も最新パッチへ

2. Budibase CVE-2026-54350 — 公開アプリの全データ参照／更新、未認証のクエリインジェクション（CVSS 4.0 評価 10 相当） CRITICAL

項目詳細
CVECVE-2026-54350（CVSS 3.1: 9.1 AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:N、CVE Brief は CVSS 4.0 10 と評価）
公表日2026-06-26 21:16 UTC（NVD 受領）＝ 2026-06-27 06:16 JST
影響バージョンBudibase < 3.39.12（OSS 低コードプラットフォーム）
修正バージョン3.39.12 以降
脆弱性種別CWE-89 SQL Injection／CWE-943 データクエリロジックの特殊文字処理不備
悪用状況公開PoCなし・能動的悪用の証拠なし（未認訪問者による攻撃経路）
  • 概要 — オープンソースの低コードプラットフォーム Budibase において、公開済み（PUBLIC）アプリの未認証訪問者が backing store（MongoDB／CouchDB／Elasticsearch／DynamoDB-PartiQL／REST+JSON ボディ）の全ドキュメントを読み出せる脆弱性。クエリ builder が公開した write query が存在する場合は全ドキュメントの一斉変更も可能。enrichContext がパラメタ値を raw JSON body に注入して JSON.parse するが、入力検証は Handlebars marker（{{／}}）のみを拒否し、JSON メタ文字（", \, }）のエスケープを行わない。パラメタ値に終端クォート + 追加キーを含めることで攻撃者が filter object に任意フィールドを持ち込み、MongoDB の collection.find() では {name: {$exists: true}} のような上書きで全件取得、updateMany では filter を全件に拡張しつつ builder 制御の $set を全件に適用
  • 被害シナリオ — 認可ミドルウェア authorized.ts は query role が PUBLIC の場合に short-circuit し、CSRF も未適用。POST /api/v2/queries/:queryId はセッション不要で x-budibase-app-id ヘッダのみ（公開アプリ URL から抽出可）で呼び出し可能。社内ツール・顧客ポータル・公開ダッシュボード構築で Budibase を使っている場合、公開アプリの背後にある全データが未認証で漏えい・改ざんされる
  • 修正内容 — 3.39.12 で入力検証・JSON エスケープロジックを修正
  • 対応 — Budibase を 3.39.12 以降に即時更新。即時適用が困難な場合は、公開アプリの PUBLIC write query を無効化し、公開アプリ全体を認証後ろに退避させ、未認証状態での /api/v2/queries/* アクセスを WAF／リバースプロキシで遮断

3. Kestra CVE-2026-53576 / CVE-2026-49869 — 認証バイパス（/configs suffix 一致）から未認証 root RCE、docker.sock マウントでホスト掌握も（CVSS 10 相当） CRITICAL

項目詳細
CVECVE-2026-53576（CVSS 3.1: 9.8 AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H）／CVE-2026-49869（CVSS 3.1: 9.8、同一エンドポイント別経路、CVE Brief は CVSS 4.0 10 と評価）
公表日2026-06-26 22:16 UTC（NVD 受領）＝ 2026-06-27 07:16 JST
影響バージョンKestra < 1.0.45／1.3.21（OSS イベント駆動オーケストレーションプラットフォーム）
修正バージョン1.0.45／1.3.21 以降
脆弱性種別CWE-288 認証バイパス（迂回経路）／CWE-287 不適切な認証／CWE-78 OS コマンドインジェクション／CWE-918 SSRF／CWE-94 コードインジェクション／CWE-184 不完全な拒否リスト
悪用状況公開PoCなし・能動的悪用の証拠なし（未認証のネットワーク攻撃者が RCE まで到達可能）
  • 概要 — Kestra はオープンソースのイベント駆動型ワークフローオーケストレーションプラットフォーム。REST API の認証フィルタ @Filter("/api/v1/**") は /configs で終わる任意の path を public な instance-config エンドポイントと誤認し、Basic-Auth をバイパスして転送する。Kestra はパスセグメントを呼び出し側が選ぶ URL 構造（/api/v1/{tenant}/flows/{namespace} 等）を採用するため、匿名呼び出し元は末尾セグメントに configs を選ぶだけで任意テナントの flow-create／execution-trigger ルートに到達可能。Shell／Process タスクを含む flow を作成して実行すると worker コンテナ内で root として任意コード実行が成立
  • 被害シナリオ — 公式 docker-compose.yml は /var/run/docker.sock をマウントするため、root 化した worker がホスト Docker daemon にも到達し、ホスト側コンテナ・シークレット・ネットワークを掌握する
  • 修正内容 — 1.0.45／1.3.21 で suffix 一致を exact 一致に修正し、認証バイパス経路を除去。シェル／プロセス系スクリプトプラグインの既定有効化は据え置きだが、未認証経路からの flow 実行を遮断
  • 対応 — Kestra を 1.0.45／1.3.21 以降に即時更新。即時適用が困難な場合は、Kestra をインターネットに直接露出させず、認証プロキシ／VPN 背後に退避。/var/run/docker.sock の Kestra コンテナへのマウントを再検討し、可能なら読取専用または破棄。CI/CD 基盤としてインターネット公開しているセルフホスト Kestra が最優先

4. OpenProject CVE-2026-46386 — 公式 Docker イメージのデフォルト SECRET_KEY_BASE + Marshal cookie でログインユーザーから RCE（CVSS 9.9） CRITICAL

項目詳細
CVECVE-2026-46386（CVSS 3.1: 9.9 AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H）
公表日NVD 受領: 2026-06-26〜27。CISA-ADP は 2026-06-27 00:17 UTC にレコード追記
影響バージョン公式 openproject/openproject Docker イメージ全既定構成（修正版未公表の記載あり、最新パッチ追跡必要）
修正バージョン修正版はアドバイザリ本文中で空白。後続の OpenProject 17.3.3／17.4.1 に同梱の関連修正（CVE-2026-52780 cache store poisoning RCE）と併せて最新版への更新を推奨
脆弱性種別CWE-502 信頼できないデータのデシリアライゼーション／CWE-798 ハードコード認証情報／CWE-1392 デフォルト認証情報の使用／CWE-1188 リソースの安全でない既定初期化
悪用状況公開PoCなし・能動的悪用の証拠なし（ログイン済ユーザーから攻撃起点）
  • 概要 — オープンソースのプロジェクト管理ソフト OpenProject の公式 Docker イメージは ENV SECRET_KEY_BASE=*** をデフォルトの Rails master key として出荷。さらに cookies_serializer = :marshal と組合わることで、ログイン済み任意のユーザーが /my/two_factor_devices の cookie reader 経由で決定論的に Marshal デシリアライゼーションを起こし、RCE に到達しうる
  • 同日同クラスター — CVE Brief 6/27 版は OpenProject クラスターとして、本件（CVE-2026-46386）、cache store poisoning からの RCE（CVE-2026-52780、修正 17.3.3／17.4.1）、SQL injection（timestamps パラメタ、CVE-2026-52680 系）、IDOR（プロジェクト管理者権限で他プロジェクトフォルダACL乗っ取り）を一括取り上げ。ログインユーザーを起点に据え置いた OS コマンド実行／DB 操作権限の取得が開示
  • 被害シナリオ — 公式 Docker イメージを変更せずに運用している全 OpenProject デプロイが脆弱。SECRET_KEY_BASE が共通値であるため、攻撃者は自環境で cookie を forge し、外部から直接 RCE 起点フローを整えることも可能。オープンなテナント・サンプルアカウントがある構成では越権リスク高い
  • 修正内容 — SECRET_KEY_BASE を起動時に強制的に生成／外部注入する運用に変更し、cookies_serializer はハイブリッド／JSON に移行することが期待される。2026-06-28 朝時点で修正版は README 文中は空白、最新リリース 17.3.3／17.4.1 で関連修正 CVE-2026-52780 が含まれるため、最新版の追従を必須とする
  • 対応 — OpenProject を最新安定版（17.4.x 系推奨）に更新。デプロイ時に SECRET_KEY_BASE を独自の強力な値で明示上書きし、再生成・ローテーションを実施。Docker compose の env を確認しデフォルト値 *** が残っていないことを検査。不要ユーザー／外部公開アカウントを閉鎖し、2FA 認証デバイス経路を監査

  • 被害シナリオ — PR 由来／fork-build／依存リポジトリ改ざん／テンプレートリポジトリ汚染／生成 AI agent の一時 checkout 上で pnpm install を実行するだけで、CI runner のシークレット・クラウドクレデンシャル・成果物アーティファクトが漏洩・汚染される。--frozen-lockfile を併用してもロックファイル自体が細工済みの場合は防げないため、信頼不能な PR 由来 lockfile は再現しない運用が必須
  • 対応 — pnpm を 10.34.2／11.5.3（可能なら 11.7.0）以降に即時更新。CI での pnpm バージョンは packageManager フィールド／corepack で pinning。pnpm-lock.yaml の diff は PR review で必ず精査（特に env lockfile・configDependencies・hoisted aliases・patchedDependencies）。信頼できない PR 由来の lockfile を CI で再利用しない。AI エージェント運用では pnpm install を実行するサンドボックスのネットワーク出口・ファイルシステム書き込み範囲を制限
