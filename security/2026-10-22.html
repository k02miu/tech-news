PHP 8.5.12 / 8.4.27 / 8.3.36 / 8.2.35 - 未認証の遠隔コード実行2件（いずれもCVSSv4.0 9.2）の修正版が公開Critical

識別子CVE-2026-109618（OOM処理の中断による内部データ未初期化）、CVE-2026-109619（解放済みメモリを指す古いグローバル状態の再利用）
影響PHP-FPM・Apache mod_php・php-cgi・FrankenPHP・LiteSpeedを含む、Webリクエストを処理するすべてのPHPインストール。修正版は 8.5.12 / 8.4.27 / 8.3.36 / 8.2.35
公開協定世界時 2026-10-21 14:00（JST 同日23:00）リリース。事前予告 2026-10-20（Security NEXT 2026/10/21、php.net News Archive 2026）
  • 事前予告どおり、協定世界時10月21日14時に修正版が公開されました。両件ともCVSSv4.0ベーススコア9.2で、未認証のリクエストから遠隔コード実行に至るものです。
  • CVE-2026-109618（RCE via OOM corruption）は、メモリ枯渇（OOM）処理が内部のリクエストデータを部分初期化のままPHPを中断させ得るため、リクエストの後処理が無効なデータを有効として扱う問題です。mod_phpではアプリケーションのコードが動く前に攻撃が成立する実証例が示されています。
  • CVE-2026-109619（RCE via stale global state）は、リクエストに紐づく内部状態が、その背後のメモリが解放された後も生存しうるため、同一ワーカーが処理する後続のリクエストが通常の初期化より前に古い状態を利用してしまう問題です。
  • PHPチームは「完全な緩和策はなく、更新が唯一の安全な選択」と明言しています。暫定措置は、memory_limit=-1をphp_admin_value等で上書き不能に設定（CVE-2026-109618）、session.upload_progress.enabled=0（PHP 8.5では fatal_error_backtraces=0）を全ワーカーの再起動を伴って適用（CVE-2026-109619）、post_max_sizeの低減やコンテナ／cgroupによる可用性境界の設定です。
  • 既にサポート外のPHP 7.4 / 8.0 / 8.1向けには最小ソースバックポートが提供されています。PHP 8.2は2026年12月31日にEOLを迎える予定です。注意点として rpms.remirepo.net は当日中の更新を提供しないため、ディストリビューションのパッケージかソースビルドへの切り替えが求められています。
  • リリース直前の同日22時30分から、国内のセキュリティ情報サイトが「利用しているソフトウェアの重大な脆弱性」を理由に予防的な緊急メンテナンスへ入る例も観測されました。PHP製のWebサイトは社内システムから公開サイトまで幅広く存在しますわ。バージョン確認を今朝のうちにお願いいたします。
