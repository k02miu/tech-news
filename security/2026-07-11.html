Critical (CVSS 8.1) Apache Kafka 4.0.x — OAUTHBEARER JWT 認証バイパス

対象Apache Kafka 4.0.0 〜 4.0.x
深刻度CVSS 8.1 (High) — 自己評価
種別認証バイパス (CWE-287)
Sourceoss-security ML
  • Apache Kafka 4.0.0 以降の OAUTHBEARER ログインパスで、JWT の有効期限 (exp) が検証されず、過去のトークンを無期限に再利用可能な認証バイパスが発見されました。
  • 攻撃者はログやエラー応答から漏洩したトークン1つでブローカーの全操作権限を取得可能。トピックデータの漏洩やクラスター状態の破壊につながります。
  • Apache 側への非公開報告に応答がなかったため、発見者により oss-security ML で公開されました（PoC は非公開）。
  • 3.x 系は異なる認証パスを使用するため影響なし。公式修正がリリースされるまで、SASL リスナーへのネットワークアクセス制限と JWT 署名鍵のローテーションが推奨されています。

Critical Apache Camel — ヘッダーインジェクション + Keycloak 認証バイパス (4件)

対象Apache Camel 4.x 各バージョン
CVECVE-2026-55994, CVE-2026-55993, CVE-2026-46726, CVE-2026-53913
深刻度High（ヘッダーインジェクション3件）, Critical（認証バイパス1件）
修正Camel 4.21.0 / 4.18.3 / 4.14.8
SourceApache Camel Security
  • CVE-2026-55994 / CVE-2026-55993 / CVE-2026-46726: 3つの Camel コンシューマーコンポーネント（camel-iggy, camel-atmosphere-websocket, camel-vertx-websocket）が外部入力を HeaderFilterStrategy なしで Camel Exchange にコピー。攻撃者は CamelHttpUri ヘッダーを注入し、SSRF 経由で環境変数やシークレットを窃取可能。
  • CVE-2026-53913: camel-keycloak のデフォルト設定では空のロールリストにより認証検証がスキップされ、任意の非 null ベアラートークンで認証をバイパス。悪用されるとコード実行に到達する可能性があります。
  • 修正バージョンへのアップグレードが推奨。暫定対応として removeHeaders('Camel*') によるヘッダー除去や WebSocket エンドポイントへの認証追加が有効です。
  • Novee Security の研究者 Lidor Ben Shitrit が camel-keycloak の脆弱性を報告。

Critical (CVSS 9.8) CVE-2026-40138 — BeyondTrust 認証前バイパス

対象BeyondTrust RS / PRA v25.3.2 以前
CVECVE-2026-40138
深刻度CVSS 9.8 (Critical) / CVSS v4.0: 9.2
種別認証前バイパス (CWE-287)
SourceBeyondTrust Advisory BT26-03
  • BeyondTrust Remote Support (RS) および Privileged Remote Access (PRA) の認証サブシステムに、認証前（pre-authentication）のバイパス脆弱性が発見されました。
  • 攻撃者は特別に細工したHTTPリクエストを送信するだけで、認証情報・セッショントークン不要で管理セッションを取得可能。認証パーサーのロジック欠陥により、検証失敗時に誤って「認証成功」状態へ遷移します。
  • 特定の IdP 統合設定に依存するものの、悪用されるとプラットフォーム全体の管理者権限を掌握され、エンタープライズネットワーク全体へのラテラルムーブメントにつながります。
  • 修正: v25.3.3 以降へアップグレード。SaaS 環境はベンダーにより4月中に修正済み。併せて管理インターフェースのインターネット公開停止、アクセスログ監査、資格情報のローテーションが推奨されています。
