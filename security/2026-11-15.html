High WordPress「Quick Page/Post Redirect」5.2.4未満 — 隠し更新機構を悪用したバックドア配布（サプライチェーン攻撃）

リスクサプライチェーン／任意コード投入
CVECVE-2026-126697
影響Quick Page/Post Redirect プラグイン 5.2.4 未満
公開NVD登録 2026-11-14 07:17 UTC（WPScan採番）
出典WPScan
  • WordPress.org で公開されていた 5.2.1 は、独自の Update Checker ライブラリ（updater/ ディレクトリ）を同梱し、更新確認先を作者自身のサーバー「anadnet.com」に向けていました。正規のディレクトリではなく作者サーバーから更新を取得する「隠し更新機構」です。
  • 2021年3月、そのサーバーは WordPress.org で後日公開された 5.2.3 とは異なる改変版 5.2.3 を配信しました。更新機構はそのまま残され、攻撃者は配信内容を差し替えることで、任意のコンテンツをページへ注入し、サイトに対して任意のコードを届けることができました。
  • 配布チャネル自体が汚染された事案です。当該プラグインを導入しているサイトは、プラグインの更新だけでなくファイル改ざんの有無も確認してくださいませ。

Critical Dokploy 0.31.1未満 — バックアップの serviceName 経由で root 権限の OS コマンドインジェクション（CVE-2026-129433、CVSSv4.0 9.4）

深刻度CVSSv4.0 9.4（Critical）
CVECVE-2026-129433
影響Dokploy 0.31.1 未満
公開NVD登録 2026-11-14 13:17 UTC
  • セルフホスト型の PaaS／デプロイ基盤 Dokploy の getComposeContainerCommand() に、認証済み組織メンバーが serviceName 引数へシェルメタ文字を混入できる OS コマンドインジェクションがあります。
  • backup.create／backup.update の tRPC 手順で細工した serviceName を保存させ、スケジュールされたバックアップ実行時に root 権限でコマンドが走り、ホスト全体を掌握され得ます。自ホストの PaaS を運用している場合は直ちに 0.31.1 以降へ更新くださいませ。

High create-ecdh 4.0.4以下（npm） — 公開鍵を検証せず不正曲線・小部分群攻撃で秘密鍵を回復（CVE-2026-129319、CVSSv4.0 8.2）

深刻度CVSSv4.0 8.2（High）
CVECVE-2026-129319
影響create-ecdh 4.0.4 以下（browserify 実装）
公開NVD登録 2026-11-14 07:17 UTC
  • Node.js の crypto.createECDH をブラウザ向けに再実装した create-ecdh の JavaScript 実装（browser.js）が、computeSecret／setPublicKey で相手の公開鍵を検証していませんでした。設定済み曲線上および素位数部分群に属することの確認がないまま、相手の点を自分の秘密鍵で乗算していました。
  • 静的な秘密鍵を再利用する相手に攻撃者が公開鍵を投入できる場合、不正曲線攻撃・小部分群攻撃で秘密鍵を小さな因子の剰余で回復され、中国剰余定理により最終的に鍵全体を復元されます。ed25519／curve25519 では低位数点も受理され、共有秘密を予測可能にされ得ます。
  • 修正は 4.0.5 以降です（GHSA-32q7-f779-hw5r、コミット 1cfaf33）。

High PrestaShop 8.2.9／9.2.1未満 — マルチショップ構成で Webservice API キーが店舗境界を越える（CVE-2026-71519・71531、各 CVSSv4.0 8.6）

深刻度CVSSv4.0 8.6（High）×2
CVECVE-2026-71519 / CVE-2026-71531
影響PrestaShop 8.2.9 未満、9.2.1 未満
公開NVD登録 2026-11-13 23:17 UTC
  • CVE-2026-71519 は破損したアクセス制御で、Webservice API キー保持者がマルチショップ構成の任意店舗の顧客レコードを読取・改変できます。shopHasRight() と saveEntityFromXml() のレコード単位の店舗所有チェック欠如を突かれ、パスワードハッシュや secure_key を窃取され、顧客のメールアドレスとパスワードを変更されてアカウントを奪取されます。

  • 対策はいずれも 8.2.9 または 9.2.1 以降への更新です（GHSA-hjwq-7qvv-qxj4、GHSA-3f36-4qv4-vfgh）。
