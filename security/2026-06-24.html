1. IBM Langflow OSS CVE-2026-10561 — PythonREPLComponentの組み込み関数インジェクション＋自動ログインで認証不要RCE（CVSS 10.0） CRITICAL

項目詳細
CVECVE-2026-10561（CVSS 3.1: 10.0 / AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H）
公表日2026-06-21（IBMセキュリティ速報）／2026-06-22 NVD公開（US時間）＝ 2026-06-23 JST／6月23日 CVE Brief でCritical筆頭
影響バージョンIBM Langflow OSS 1.0.0 〜 1.9.3
修正バージョン1.9.4 以降
脆弱性種別CWE-94 コードインジェクション（Python実行隔離の不備 ＋ 認証バイパス）
悪用状況公開PoCなし・能動的悪用の証拠なし（LANGFLOW_AUTO_LOGIN=true デフォルトで認証不要攻撃経路が成立）
  • 概要 — AIエージェントをGUIで構築できるOSS「Langflow」の PythonREPLComponent（Python Interpreter）において、get_globals() が制限付き globals 辞書を構築する際に globals_["__builtins__"] = {} を設定しない。CPythonの exec() は builtins が不在の場合に完全な builtins モジュールを自動挿入するため、import・open・eval などの組み込み関数がホワイトリストに関わらず全て利用可能になる。これに LANGFLOW_AUTO_LOGIN=true デフォルト（GET /api/v1/auto_login でクレデンシャルなしにスーパーユーザーJWT発行）が組み合わさり、完全な認証不要RCEが成立する
  • 被害シナリオ — LangflowはRAG・AIエージェントのプロトタイピング・本番運用に広く使われる。インターネット公開環境では、攻撃者が認証なしでバックエンドプロセス権限（Dockerデフォルトではroot）で任意OSコマンドを実行でき、LLMプロバイダーのAPIキー（OpenAI/Anthropic）窃取・フロー定義の盗取・改ざん・ベクトルストアのクレデンシャル（Chroma/Pinecone/Weaviate）アクセス・cronやバックドアファイルによる永続化が可能
  • 修正内容 — 1.9.4 でPython実行の隔離を修正し、builtins の明示的空設定を追加。ワークアラウンドは「なし」（IBM公式見解）
  • 対応 — Langflow OSS を 1.9.4 以降に即時更新。インターネット公開している場合は直ちにアクセスを制限。LANGFLOW_AUTO_LOGIN を無効化し、認証を必須化。プロバイダーAPIキーのローテーションを検討

2. expr-eval CVE-2026-12866 — toJSFunction() APIのサンドボックス逃脱で任意JavaScriptコード実行（CVSS 9.8） CRITICAL

項目詳細
CVECVE-2026-12866（CVSS 3.1: 9.8 / AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H、CVSS 4.0: 9.8）
公表日2026-06-22 〜 23 NVD公開（6月23日 CVE Brief でCriticalとして取り上げ）
影響バージョンexpr-eval の全バージョン（npm パッケージ）
修正バージョンパッチ未提供（公開時点）
脆弱性種別CWE-94 コードインジェクション（Function() コンストラクタ経由のサンドボックス逃脱）
悪用状況公開PoCなし・能動的悪用の証拠なし（ネットワーク経由の未認証攻撃者が実行可能）
  • 概要 — JavaScript の数式評価ライブラリ「expr-eval」の toJSFunction() APIにおいて、ユーザー制御の式がネイティブ Function() コンストラクタで直接コンパイルされる。サンドボックスが不十分なため、攻撃者は意図された数式サンドボックスを逃れてアプリケーションコンテキスト内で任意のJavaScriptコードを実行できる
  • 被害シナリオ — expr-eval はWebアプリケーションの動的計算フィールド・フォームバリデーション・設定UIなどで広く使われる。ユーザー入力を式として受け付ける箇所で toJSFunction() を使用している場合、未認証のネットワーク攻撃者がアプリケーションのセキュリティコンテキスト内で任意コードを実行可能
  • 修正内容 — パッチ未提供（CVE Brief でも「No vendor patches were available at disclosure」と記載）。代替ライブラリの使用や、toJSFunction() APIへの信頼できない入力の受け入れを停止することが推奨される
  • 対応 — toJSFunction() API に信頼できない入力を渡さない。入力バリデーション・サニタイズを厳格化し、より強力なサンドボックス保証を持つ代替式評価ライブラリへの移行を検討。パッチが出次第即時適用
  • 〈web / Node.js / JavaScript ライブラリスタックに直接関連〉

4. Hono CVE-2026-56762 / CVE-2026-47676 — Cookieヘッダー不正文字によるレスポンス分割 ＋ app.mount() のパス解析不一致でアクセス制御バイパス MEDIUM

項目詳細
CVECVE-2026-56762（CVSS 3.1: 5.3 / AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:L）／CVE-2026-47676（CVSS 3.1: 5.3 / AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:N）
公表日CVE-2026-56762: 2026-06-23 NVD公開／CVE-2026-47676: NVD公開（6月23日 CVE Brief で取り上げ）
影響バージョンCVE-2026-56762: Hono 4.12.11 以前／CVE-2026-47676: Hono 4.12.20 以前
修正バージョンCVE-2026-56762: 4.12.12 以降／CVE-2026-47676: 4.12.21 以降
脆弱性種別CVE-2026-56762: CWE-113 HTTPレスポンス分割（Cookie名の不正文字検証欠如）／CVE-2026-47676: CWE-444 HTTPリクエストスマグリング（マウントプレフィックスの未デコードパス切り取り）
悪用状況公開PoCなし・能動的悪用の証拠なし（いずれも未認証のネットワーク攻撃者が実行可能）
  • CVE-2026-56762 概要 — Hono の setCookie()・serialize()・serializeSigned() 関数がCookie名の書き込みパスで不正文字（\r・\n 等の制御文字）を検証しない。ユーザー制御のCookie名を渡すと不正な Set-Cookie ヘッダー値が生成される。Node.js・Cloudflare Workers 等のモダンランタイムでは不正ヘッダー値は拒否されてランタイムエラーとなり、アプリケーションのクラッシュ・サービス停止（DoS）を引き起こす
  • CVE-2026-47676 概要 — app.mount() がマウントプレフィックスを生URLパス名から切り取る一方、ルートマッチングはパーセントデコード後のパスに対して行われる。パスにパーセントエンコードされたマルチバイト文字が含まれる場合、この不一致によりプレフィックスが誤った位置で切り取られ、マウントされたサブアプリケーションが誤ったパスを受信する。攻撃者はパーセントエンコードされたマルチバイト文字を用いて、マウントプレフィックスによるパスベースのアクセス制御をバイパスし、保護されたリソースやサブアプリケーションにアクセス可能
  • 影響 — Hono はCloudflare Workers・Bun・Deno・Node.js 等の多様なJavaScriptランタイムで動作する軽量Webフレームワーク。Cookie名の制御文字注入はDoS、パス解析不一致はアクセス制御バイパスにつながり、エッジサーバー・APIゲートウェイでの利用時に特に注意が必要
  • 対応 — CVE-2026-56762 は Hono 4.12.12 以降に更新。Cookie名にユーザー入力を使用する場合は不正文字を拒否する入力バリデーションを実装。CVE-2026-47676 は Hono 4.12.21 以降に更新。app.mount() でセキュリティ感受性の高いパスプレフィックスを使用している場合は修正後に再テストを実施
  • 〈Hono / web フレームワークスタックに直接関連〉

5. vLLM 複数CVE — マルチテナント推論でのGPUメモリ情報漏洩・DoS・活性化関数ロードでのコード実行バイパス HIGH

項目詳細
CVECVE-2026-53923（GPUメモリ情報漏洩）／CVE-2026-54235（temperature=NaN/Infinity バリデーションバイパス）／GHSA-q8gq-377p-jq3r（活性化関数ロードのセキュリティチェックバイパス→任意コード実行）
公表日CVE-2026-53923・54235: 2026-06-22 NVD公開（US時間）＝ 2026-06-23 JST／GHSA-q8gq-377p-jq3r: 2026-06-14 GitHub公開
影響バージョンCVE-2026-53923: vLLM 0.5.5 〜 0.23.1rc0未満／CVE-2026-54235: 0.23.1rc0未満／GHSA-q8gq-377p-jq3r: 該当バージョン
修正バージョンCVE-2026-53923・54235: 0.23.1rc0 以降
脆弱性種別CWE-200 情報漏洩（GPU未初期化メモリ）／CWE-1287 入力型検証不備／CWE-94 コードインジェクション（assert文バイパス）
悪用状況公開PoCなし・能動的悪用の証拠なし（6月23日 CVE Brief でCritical/Highとして取り上げ）
  • CVE-2026-53923 概要 — vLLM の GGUF デ量子化CUDAカーネルが tensor 次元を int64_t から int に切り詰めることで、出力テンソルの一部のみが処理される。未処理部分はGPUの未初期化メモリを保持し、マルチテナント推論環境では他ユーザーの推論リクエストのテンソルデータが漏洩する可能性がある
  • CVE-2026-54235 概要 — temperature のバリデーションが比較演算子（< >）を使用しており、Python の IEEE 754 浮動小数点セマンティクスで NaN と正の Infinity は全ての比較で False と評価される。これによりバリデーションをすり抜けた値がGPUサンプリングカーネルに伝播し、未定義動作やCUDAエラーで推論ワーカーをクラッシュさせる
  • GHSA-q8gq-377p-jq3r 概要 — 活性化関数のロード時のセキュリティチェックが assert 文で実装されており、Pythonの最適化モード（-O）で実行された場合に assert が無効化されてセキュリティチェックがバイパスされる。結果として任意のコード実行が可能になる
  • 被害シナリオ — vLLM は大規模LLM推論サービングのデファクトスタンダード。マルチテナント環境（共有GPU・推論API提供）でのGPUメモリ漏洩はテナント間のデータ分離を破り、DoS・コード実行は推論インフラ全体の乗っ取りにつながる
  • 対応 — vLLM を 0.23.1rc0 以降に更新。マルチテナント推論環境では特に CVE-2026-53923 の修正を優先。Python最適化モード（-O）での運用は避け、GHSA-q8gq-377p-jq3r の修正を確認
