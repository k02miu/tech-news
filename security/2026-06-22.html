1. Prefect CVE-2026-5366 — Git引数インジェクションでワーカー上の任意コマンド実行（CVSS 9.9） CRITICAL

項目詳細
CVECVE-2026-5366（CVSS 3.0: 9.9 / AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H）
公表日2026-06-20（米国時間）／2026-06-21 JST（NVD 登録）
影響バージョンPrefect 3.6.23 以前（GitRepository ストレージクラス）
修正バージョン3.6.25.dev7 以降（PR #21384）
脆弱性種別CWE-94 コード生成の不適切な制御（引数インジェクション）
悪用状況CISA KEV 未登録（公開PoCなし、内部関係者・乗っ取りアカウントからの悪用が現実的）
  • 概要 — Pythonデータパイプライン自動化ツール「Prefect」の GitRepository ストレージクラス（src/prefect/runner/storage.py）において、gitリポジトリからコードを取得する際の commit_sha パラメータが検証されず、そのままgitコマンドの引数に渡される。攻撃者は --upload-pack=touch /tmp/pwned のようなgitオプションを commit_sha に紛れ込ませることで、ワーカー（作業マシン）上で任意のコマンドを実行可能。また directories パラメータも sparse-checkout 操作で同様にgitフラグインジェクションに悪用可能
  • 被害シナリオ — 複数人・チームで共有するセルフホストPrefect環境では「デプロイを登録できる」程度の低権限ユーザーがこの穴を突ける。しかもCVSS評価でスコープ変更（S:C）が含まれており、自分の枠を越えて共有ワーカーや他チームの処理基盤にまで侵入が及ぶ。ワーカーはデータ倉庫（Snowflake等）・AWS/GCPアクセスキー・各種トークンを握る立場にあり、乗っ取られれば全社のデータへの最短経路になる
  • 修正内容 — PR #21384 で commit_sha を正規表現 ^[0-9a-fA-F]{4,64}$（16進数4〜64文字）に限定し、directories に -- セパレータを追加。この修正PRはAIエージェント「Devin」が自動生成し、2026年4月2日にメンテナがマージ。修正版は 3.6.25.dev7 として配布
  • 対応 — セルフホストPrefectのサーバーとワーカーの両方を 3.6.25.dev7 以降（できれば安定版）に更新。デプロイ登録権限を見直し最小化。対象バージョンを共有環境で運用していた場合はワーカーがアクセスできたクラウドキー・DB接続情報・トークンを漏洩前提でローテーション。ワーカーの権限を処理ごとに最小限に縮小

2. BerriAI litellm CVE-2026-12770 / 12771 / 12772 — LLMプロキシの認可制御欠陥3件、非管理者の権限昇格 HIGH

項目詳細
CVECVE-2026-12770（CVSS 5.3 Medium）／CVE-2026-12771（Critical）／CVE-2026-12772
公表日2026-06-21（3件連続公開、UTC 1時〜2時＝JST 10時〜11時）
影響BerriAI litellm（Python LLMプロキシサーバー）
影響バージョン12770: 1.63.1 以前 ／ 12771・12772: 1.82.2 以前
修正12770: PR #23781 ／ 12772: 1.83.0 以降
悪用状況3件ともリモート攻撃可能、PoC公開済み（12771は高複雑度・悪用困難との評価）
  • 概要 — LLM APIプロキシとして広く使われる「litellm」に、6月21日に認可制御の欠陥3件が連続公開された。CVE-2026-12770はAdmin Key Handler（key_management_endpoints.py）の不適切な認可。INTERNAL_USER権限のユーザーが /key/block・/key/unblock で他ユーザーのキーをブロック/ブロック解除でき、/key/update で自分のキーの max_budget を管理者権限なしに引き上げ可能。CVE-2026-12771はM2M JWT Handler（user_api_key_auth.py）の不適切な認可（Critical、ただし高複雑度・悪用困難）。CVE-2026-12772はPROXY_ADMIN DB API Key Generator（login_utils.py の authenticate_user）でセッション有効期限の問題
  • 影響 — litellmプロキシは複数LLMプロバイダーのAPIキーを一元管理する役割を持つ。認可制御の欠陥により、低権限ユーザーが他ユーザーのAPIキーを操作・予算上限を回避でき、AI推論コストの不正増大やサービス妨害が可能。マルチテナント環境での影響が大きい
  • 修正内容（PR #23781） — _check_key_admin_access() ヘルパーを追加し、呼び出しがproxy admin / team admin / org admin であることを検証。block_key・unblock_key はDB変更前にチェック、update_key_fn は max_budget 変更時に管理者チェックを強制。非管理者は自分のキーの非予算フィールド更新のみ可能
  • 対応 — litellm を最新版（1.83.0 以降推奨）に更新。PR #23781 の修正が含まれるバージョンにアップグレード。プロキシの管理エンドポイントへのアクセスをネットワークレベルで制限し、INTERNAL_USER権限の付与を最小化
  • 〈Python / AI プロキシスタックに直接関連〉

🔴 Flowise CVE-2024-58351 — AIワークフロービルダーのoverrideConfig経由RCE（CVSS 9.8） CRITICAL

項目詳細
CVECVE-2024-58351（CVSS 3.1: 9.8 ／ CVSS 4.0: 9.3）
公表日2026-06-20（NVD公開）／2026-06-21 CVE Brief で注目 CVE として取り上げ
影響バージョンFlowise 2.1.4 未満
修正バージョン2.1.4 以降
脆弱性種別設定インジェクション → リモートコード実行（vm2サンドボックスエスケープ）
  • 概要 — オープンソースのAIワークフロー/LangChainビジュアルビルダー「Flowise」において、overrideConfig オプション経由で設定が Chainflow 実行プロセスにインジェクション可能。攻撃者が悪意のある設定を注入することで vm2 サンドボックスをエスケープし、サーバー上で任意のコードを実行できる。Flowiseはブラウザからドラッグ＆ドロップでAIエージェントやRAGパイプラインを構築できるツールで、社内AI基盤として導入する組織が増加中
  • 背景 — CVE ID は2024年代だが、NVDへの本格公開は2026年6月20日。6月21日の CVE Brief で「5つのCritical CVE」のひとつとして取り上げられた。同種の「外部入力をそのまま実行してしまう」型の脆弱性は Prefect（CVE-2026-5366）や Langflow などデータ・AI系ツールで繰り返し発生しており、AI基盤のサプライチェーンリスクとして注目すべきパターン
  • 影響 — Flowise をインターネット公開している環境では、認証なしまたは低権限でRCEが成立し得る。AIワークフロービルダーはLLM APIキー・ベクトルDB接続情報・プロンプトテンプレート等の機密情報を保持するため、乗っ取られればAIインフラ全体が侵害される
  • 対応 — Flowise を 2.1.4 以降に更新。インターネット公開している場合は即座にアクセス制限（リバースプロキシ・認証）を確認。overrideConfig の入力検証とサンドボックス設定を監査
