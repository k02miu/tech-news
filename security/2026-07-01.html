2. AWS Application Load Balancer / Amazon CloudFront + AWS WAF — HTTP/2 リクエストボディ断片化による WAF body inspection バイパス CRITICAL

項目詳細
CVECVE-2026-13763（AWS ALB + WAF、CVSS 3.1 9.8 相当）／CVE-2026-13762（Amazon CloudFront + WAF、CVSS 3.1 9.8 相当）
公表日NVD 受領: 2026-06-29 16:17 UTC（= 2026-07-01 01:17 JST 境界付近）。CISA ADP SSVC エンリッチ: 2026-06-29 20:50 UTC。CVE Brief Tuesday (6/30) で広く表面化
影響CVE-2026-13763: AWS WAF 有効な ALB で HTTP/2 target group 使用時、リクエストボディを複数フレームに断片化することで WAF managed rule body inspection を部分的にバイパス可能。CVE-2026-13762: CloudFront + WAF で同種の HTTP/2 frame fragmentation による body inspection バイパス
修正CVE-2026-13763: 顧客側 action 必要 — ALB target group で "Inspect after sufficient data" 設定を有効化（AWS ドキュメント 参照）。CVE-2026-13762: サーバー側で修復済み・顧客の action 不要
悪用状況CVE-2026-13763: CISA SSVC exploitation=none。CVE-2026-13762: CISA SSVC exploitation=poc
  • 概要 — AWS が 2 件の HTTP/2 request body inspection バイパス脆弱性を NVD に登録。いずれも AWS WAF が有効な ALB / CloudFront で、HTTP/2 の request body を意図的に複数フレームに断片化することで WAF の body inspection ルールを回避する攻撃手法。CWE-444 (Inconsistent Interpretation of HTTP Requests / Request Smuggling 系)
  • 被害シナリオ — WAF managed rules が malicious payload を含む request body を完全検査せず、バックエンドへ到達させてしまう。WAF bypass → SQL injection / XSS / command injection ペイロードが WAF を通過する余地
  • 対応 — ⚠ CVE-2026-13763 は顧客 action 必須: ALB HTTP/2 target group を使用する全環境で "Inspect after sufficient data" target group attribute を有効化。Terraform / CloudFormation IaC で一斉適用を推奨。CVE-2026-13762 (CloudFront) は AWS 側で修復済みのため action 不要。両 CVE とも NVD enrichment 待ち状態で CVSS の NVD 公式評価は未出 — ベクトルから 9.8 相当と推定
  • 〈AWS スタックの WAF / ALB / CloudFront を利用する全環境に直接関連。IaC (Terraform / CloudFormation) 管理環境で即時対応可能〉

3. Google MCP Toolbox for Databases — URL builder パストラバーサル（設定クレデンシャル漏洩） CRITICAL

項目詳細
CVECVE-2026-11720（CVSS 4.0 評価: VC:H/VI:H/VA:N — CVSS 3.x 提供なし、概ね 9.3 相当）
公表日NVD 受領: 2026-06-29。CISA ADP エンリッチ: 2026-06-29 15:16 UTC。CVE Brief Tuesday (6/30) で表面化
影響googleapis/mcp-toolbox の HTTP tool URL builder が user-controlled pathParams を tool path に展開後、ResolveReference で解決。dot segments (../) が正規化されるため、攻撃者は directory traversal で operator 設定の path scope を逸脱して同一 host 上の意図しない endpoint にリクエストを送出可能。toolbox に設定された credentials（API key / Bearer token 等）を forward したまま
修正バージョンNVD・GitHub Advisory ともに未公開（パッチ待ち）
悪用状況CISA SSVC: exploitation=none, automatable=yes
  • 概要 — Google が提供する MCP Toolbox for Databases に path traversal 脆弱性。tool path template に渡す pathParams で ../ を使い、制限された API path（例: /api/v1/users/{{.id}}）から権限外 endpoint（例: /admin/secrets）へのアクセスが可能。toolbox が保持する認証情報を付与したままリクエストが送られるため、機密 endpoint への認証付きアクセス漏洩
  • 被害シナリオ — MCP-based agent が toolbox を経由して DB/API にアクセスする構成で、path param を攻撃者が制御可能な場合、toolbox の credentials を使って管理 endpoint へアクセス。agent 経由の transitive credential leak
  • 対応 — パッチ未公開。暫定対処: toolbox に渡す pathParams の入力検証を upstream で強化（../ 文字列の拒否・URL path の allowlist 化）。toolbox credentials の最小権限化・scope 限定。MCP agent 構成で user-controlled path param が toolbox に到達しないよう入力ルーティングを見直し
  • 〈MCP / agent tooling スタック・Hermes Agent / OpenClaw の MCP server 利用構成に直接関連〉

  • 概要 — SAML Replay — Rancher の SAML Assertion Consumer Service (ACS) handler が SAML assertion の one-time use を強制していなかった。攻撃者が victim の SAML response + pre-auth state cookie を取得（network interception / log access / XSS 経由）すれば、同一 signed response を再提出して victim として別 session を確立可能。全 SAML provider 共通 handler (pkg/auth/providers/saml/saml_client.go) で影響

  • 〈AWS / Azure / GCP 上で Rancher で Kubernetes クラスタを管理する環境に直接関連。SAML SSO を利用する全 Rancher 環境で要即時対応〉
