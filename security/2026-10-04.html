Bouncy Castle for Java 1.86 / LTS 2.73.13 - 暗号ライブラリに複数の脆弱性、MLSの資格情報束縛不備はCVSS 9.2 CRITICAL

対象Bouncy Castle for Java 1.86 未満（bcprov-jdk18on 等）、Bouncy Castle for Java LTS 2.73.13 未満
修正版1.86 / LTS 2.73.13
主要CVECVE-2026-71885（CVSSv4.0 9.2 / MLSでX.509資格情報がリーフのsignature_keyへ束縛されず成りすまし）、CVE-2026-71888（8.7 / CMS AuthenticatedDataのダイジェスト検証不整合）、CVE-2026-71889（8.7 / PKIXCertPathReviewerがX.509証明書ポリシーを検証せず）、CVE-2026-71883（8.2 / LTSのネイティブパケット暗号が呼び出し元の鍵・IV・AAD配列を解放）、CVE-2026-85515（8.2 / 切り詰めたOpenPGP暗号文を無検査で受理）ほか
公開NVD登録 2026-10-03 18:17 JST、GitHub Advisory 2026-10-03
  • Java基盤で広く使われる暗号・証明書・OpenPGP・MLSライブラリでございます。Java／SpringBoot環境でTLS、署名検証、CMSやOpenPGPの処理に用いている場合は影響範囲のご確認をお勧めいたしますわ。
  • とりわけCVE-2026-71885は、MLS（RFC 9420）の実装がリーフの署名をリーフ自身が持つsignature_keyで検証する一方、資格情報のX.509証明書チェーンを保存するだけで解析・検証していなかった問題でございます。独立した資格情報審査なしに外部コミットを受理する構成では、未認証の攻撃者が被害者のX.509アイデンティティでグループへ入り込み、被害者を追い出し、現エポックを導出して以降のメッセージを復号できます。basicクレデンシャルのみの構成は影響を受けません。
  • ほかにも、OpenPGPの第三者証明・サブキー束縛の検証漏れ（CVE-2026-71886 / 71887）、BLS12-381の鍵検証不備（CVE-2026-71891）、レガシーPBES1／PKCS#12鍵導出が信頼できない入力の反復回数を用いる問題（CVE-2026-97873）などが含まれます。1.86 または LTS 2.73.13 以降への更新をご検討くださいませ。
