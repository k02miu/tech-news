undici（Node.js HTTPクライアント）- リダイレクト時のキャッシュ汚染と機密ヘッダ漏えいなど8件 High

CVECVE-2026-116592（CVSSv3.1 7.4）ほか、CVE-2026-120415 / 120423 / 120474 / 116630 / 120222 など計8件
影響undici 7.0.0〜7.30.1、8.0.0〜8.12.3（CVE-2026-116592 は 7.30.1 および 8.12.2〜8.12.3）
修正各系列の修正版へ更新（GitHub Security Advisory を参照）
  • CVE-2026-116592（7.4）: origin を持たない Agent で redirect と shared cache のインターセプタを併用すると、最終ホップのみを見て保存可否を判断するため、信頼できない origin を経由して信頼済み origin に戻るリダイレクトが信頼済みキーでキャッシュされる。中間ホップの Vary は失われ、Authorization や Cookie で変化する応答が別利用者に返り得る。CVE-2026-109829 の修正を迂回する。
  • CVE-2026-120415（5.9）: リダイレクト時に Authorization・Cookie・Proxy-Authorization・Host を削除する処理が、リクエストヘッダを「名前と値のタプル配列」（Object.entries など正当な入力形式）で渡すとヘッダ名が一致せず削除されない。cache や deduplicate のインターセプタを外側に重ねていると、保持された機密ヘッダがクロスオリジンのリクエストへ直列化され、資格情報が漏えいする（CVE-2024-30260 の修正に対する表現依存の迂回）。
  • CVE-2026-120423（5.9）: fetch が Subresource Integrity のメタデータを空白1つで分割して検証するため、SRI 文法の複数ハッシュ記載を正しく扱えない。
  • CVE-2026-120474（6.5）／CVE-2026-116630（5.9）／CVE-2026-120222（5.9）: redirect と shared cache の併用時のキャッシュ取り扱い、条件付き再検証、応答処理中の例外などに起因する不適切なキャッシュ保存。

Claude Code v2.1.319 - auto mode の安全チェック欠如時に拒否へ、権限プロンプトの扱いを追加 情報

版v2.1.319（npm 公開 2026-11-06 17:04 UTC / JST 2026-11-07 02:04）
種別セキュリティ関連の挙動変更を含むアップデート（CVE の記載なし）
  • テレメトリーやフィーチャーフラグが無効な環境（LLMゲートウェイ配下を含む）では、サーバー側で確認できない呼び出しをビルトイン分類器へフォールバックさせず、確認するか拒否する挙動に変更（CLAUDE_CODE_AUTO_MODE_SERVER=0 で従来動作を維持）。ゲートウェイ配下では CLAUDE_CODE_AUTO_MODE_SERVER=1 でサーバー側チェックを有効化できる。
  • permissions.denyInsteadOfPrompting 設定を追加。権限プロンプトを待つツール呼び出しを拒否したうえでターンを継続できる。

  • Bash の deny／ask ルールが引用符付きの語を含むコマンドを取りこぼす問題、権限ルールや autoMode 設定が非常に大きい場合に理由を示さず拒否する問題、設定ファイルや ~/.claude.json がディスク満杯時に空・途中で切れる問題なども修正。
