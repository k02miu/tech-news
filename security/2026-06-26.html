1. Google Gemini CLI / run-gemini-cli CVE-2026-12537 — コンテナランチャーでのOSコマンドインジェクション、悪意ある .gemini/.env 経由でCI/CD実行前にホストレベルRCE（CVSS 4.0: 10.0） CRITICAL

項目詳細
CVECVE-2026-12537（CVSS 4.0: 10.0 / AV:N/AC:L/AT:N/PR:N/UI:N/VC:H/VI:H/VA:H/SC:H/SI:H/SA:H）
公表日2026-06-24 21:38 UTC（NVD公開）＝ 2026-06-25 06:38 JST／6月25日 CVE Brief でCritical筆頭として取り上げ
影響対象Google Gemini CLI（gemini コマンド） バージョン 0.39.1 未満／run-gemini-cli GitHub Action バージョン 0.1.22 未満（ヘッドレスCIプラットフォーム上で動作するコンテナランチャー）
修正バージョンGemini CLI 0.39.1 以降／run-gemini-cli GitHub Action 0.1.22 以降
脆弱性種別CWE-78 OSコマンドインジェクション（CWE-20 不正入力検証としても分類）— コンテナランチャーが .gemini/.env をロードする際、agentのサンドボックス初期化より前にホスト上で任意OSコマンドが実行される
悪用状況公開PoCなし・能動的悪用の証拠なし（未認証の攻撃者が .gemini/.env 経由でホストレベル任意コード実行可能）
  • 概要 — Google Cloud が公開しているオープンソースのAIコーディングエージェントCLI「Gemini CLI」および公式GitHub Action「run-gemini-cli」のコンテナランチャーにおいて、.gemini/.env 設定ファイルの入力検証が不十分。攻撃者が悪意ある .gemini/.env をリポジトリに仕込んだ状態でCI/CDワークフローを起動すると、agent のサンドボックスが初期化される前にホストOS上で任意のコマンドが実行される。CI/CDという信頼された実行コンテキスト上で動作するため、CIランナーのトークン・クラウドクレデンシャル・成果物アーティファクトへのアクセスが一举に可能になる
  • 被害シナリオ — Gemini CLI はAnthropic社のClaude Codeと同位置づけの対話型コーディングエージェント。PR経由で .gemini/.env を書き換えられる権限を持つ攻撃者（フォークPR・メンテナ権限奪取・依存リポジトリの改ざん等）は、CI/CDの実行直後に任意コマンドを実行してランナーを制御し、シークレット窃取・本番デプロイ汚染・サプライチェーン下流汚染を実行できる。gemini/.env を信頼せずにCIを実行していた組織は影響を受けないが、多くのテンプレートでは .gemini/ ディレクトリ内のファイルを透過的にCIに読み込ませる設定がなされている
  • 修正内容 — 0.39.1 / 0.1.22 でコンテナランチャーの .env 解析ロジックを修正し、コマンド注入経路を除去。修正版への即時更新が推奨される
  • 対応 — Gemini CLI を 0.39.1 以降、run-gemini-cli GitHub Action を 0.1.22 以降に即時更新。CI/CD環境上の .gemini/.env は信頼できないソース由来のファイルを取り込まない設定に変更し、ファイル完全性監視を有効化。CIランナー上のシークレット権限を最小化し、PRオーサーに .gemini/.env 編集権限を与えない運用に見直し。Anthropic Claude Code を使用する場合は同種の .env / 設定ファイル読み込み経路について、信頼できないPRのCIでの読み込みを停止することを推奨

2. Mistune CVE-2026-49851 — Python Markdown パーサーの parse_link_text() で二次時間CPU枯渇DoS（CVSS 8.7） HIGH

項目詳細
CVECVE-2026-49851（CVSS 3.1: 8.7 / AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H、CVSS 4.0: 8.7）
公表日NVD: 2026-06-24（6月25日 CVE Brief / Amazon Linux Security Center で取り上げ）
影響バージョンMistune < 3.3.0（3.2.x 以前）— Python Markdown パーサ
修正バージョンMistune 3.3.0 以降
脆弱性種別CWE-400 制御不能な資源消費（parse_link_text() 内の正規表現ループによる O(n²) 動作）
悪用状況公開PoCなし・能動的悪用の証拠なし（未認証のネットワーク攻撃者がMarkdown入力経由で実行可能）
  • 概要 — Python 用 Markdown パーサ「Mistune」は FastAPI・Django・Flask・静的サイト生成器などWebアプリケーションのMarkdownレンダリングで広く使用。今CVEは parse_link_text() 関数が連続する [ 文字を含む入力を処理する際、ループ内部で同じ正規表現による部分文字列の再スキャンを繰り返し、概ね O(n²) のCPU時間を要する。攻撃者が短いMarkdownペイロード（多数の連続 [）を投稿するだけでサービス停止が成立する
  • 被害シナリオ — Markdown をユーザー入力として受け付けるWebサービス（コメント欄、Wiki、フォーラム、ドキュメントサイト、RAGパイプラインのテキスト正規化処理）では、未認証のリクエスト1つでワーカースレッドを長時間専有し、サービス全体の劣化・停止を引き起こし得る
  • 修正内容 — 3.3.0 で parse_link_text() のスキャン戦略を修正し、線形時間動作に変更。修正版への即時更新が推奨される
  • 対応 — Mistune を 3.3.0 以降に更新。即時適用が困難な場合は、ユーザー入力のMarkdownサイズ上限・連続 [ の上限を設ける入力バリデーションを補償的制御として実装。レンダリングを専用ワーカーで実行しタイムアウトを設ける設計も有効

CVECVE-2026-55454（CVSS 3.1: 9.9 / AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H）／CVE-2026-55455（CVSS 9.8 / SSRF）

悪用状況公開PoCなし・能動的悪用の証拠なし（認証済低権限ユーザーからの攻撃経路）
  • CVE-2026-55454 概要 — Appsmith はオープンソースの社内ツール・管理画面ビルドプラットフォーム。標準Docker Compose構成ではバンドルCaddyリバースプロキシの管理APIが 0.0.0.0:2019 上で認証なしで listen する。docker-compose.yml はこのポートをホスト公開しないものの、Appsmithサーバープロセス自身または SSRF脆弱性（CVE-2026-55455）経由で http://0.0.0.0:2019/ に POST /load を発行すると、実行中のCaddy設定を完全に置き換え、リバースプロキシを攻撃者が掌握できる
  • CVE-2026-55455 概要 — Appsmith のHTTPリクエスト機能においてSSRF。CVE-2026-55454 と連鎖することで、低権限の認証済ユーザーが前段のCaddy管理APIに到達し、プロキシの完全乗っ取りに至る。CVE-2026-55454単独でも Caddy設定を書き換えることで内部サービス横断アクセス・トラフィック傍受・不正ルーティングが成立
  • 被害シナリオ — Appsmithは社内管理画面で広く使われる。低権限ユーザー（一般従業員・請負業者・外部テナント）からの攻撃経路が成立する環境では、バックエンドAPI・DB・社内サービスへのプロキシ化・認可の迂回が可能。テナント分離がAppsmith上で設計されているSaaSではテナント間渗透リスク
  • 修正内容 — 2.1 でCaddy管理APIのバインドアドレス・認証を修正し、SSRF 入力検証を強化。アップデートが第一対応
  • 対応 — Appsmith を 2.1 以降に更新。即時更新が困難な場合は、コンテナ内部からの 2019 ポートへのアクセスを拒否するネットワークポリシーを適用し、低権限ユーザーのHTTPリクエストプラグイン権限を見直し
