1. Crawl4AI CVE-2026-56265 — Docker APIサーバーのハードコードJWT鍵で認証バイパス→完全乗っ取り（CVSS 9.8） CRITICAL

項目詳細
CVECVE-2026-56265（CVSS 3.1: 9.8 / AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H、CVSS 4.0: 9.3）
公表日2026-06-21 22:26 JST（NVD公開）／2026-06-22 の CVE Brief で注目CVEの筆頭として取り上げ
影響バージョンCrawl4AI 0.8.6 以前（Docker APIサーバー）
修正バージョン0.8.7 以降
脆弱性種別CWE-798 ハードコードされた認証情報（JWT署名鍵のデフォルト固定）
悪用状況公開PoCなし・能動的悪用の証拠なし（デフォルト鍵を知る者なら誰でもトークン偽造可能）
  • 概要 — LLM/RAGパイプライン向けのオープンソースWebクローリングツール「Crawl4AI」のDocker APIサーバーにおいて、JWT署名鍵がハードコードされたデフォルト値で出荷されていた。攻撃者はこの既知のデフォルト鍵を使って任意ユーザーの有効な認証トークンを偽造でき、認証機構を完全にバイパスして保護された全機能へフルアクセスを得る
  • 被害シナリオ — Crawl4AIはAIエージェント・RAGのデータ収集段階で広く使われ、クロール対象URL・認証クレデンシャル・抽出設定を保持する。Docker APIサーバーをインターネット公開または社内ネットワークに露出している環境では、認証なしでAPIを完全掌握され、クロールジョブの乗っ取り・設定の改ざん・接続先システムへの横展しが可能
  • 修正内容 — 0.8.7 でデフォルトJWT署名鍵を廃止し、適切な鍵管理に移行。即時アップグレードを推奨
  • 対応 — Crawl4AI を 0.8.7 以降に即時更新。アップグレードが困難な場合は Docker APIサーバーへのネットワークアクセスを信頼できるネットワークのみに制限し、デフォルトJWT署名鍵を独自の値に変更。不審な認証トークンの利用パターンを監視
  • 掲載の補足 — NVD公開は前号対象期間末尾（6/21 22:26 JST）に近く、前号では取り上げられなかったが、6/22 CVE Brief でCritical筆頭に挙げられたため本号で取り上げる

CVECVE-2026-11746（CVSS 4.0: 9.4 / AV:A/AC:L/AT:N/PR:N/UI:N/VC:H/VI:H/VA:H/SC:H/SI:H/SA:H）
公表日2026-06-22 11:35 JST（NVD公開、米国時間 6/21）
影響バージョンcentraldogma-server 0.83.x 以前（ZooKeeperレプリケーション有効時）
修正バージョン0.84.0 以降
脆弱性種別CWE-798 ハードコードされた認証情報（レプリケーション秘密鍵の既知デフォルト）
悪用状況公開PoCなし・能動的悪用の証拠なし（隣接ネットワークからZooKeeperクライアントで既知秘密鍵を提示するだけで悪用可能）
  • 概要 — LY Corporation（旧LINE）が開発・運用するJavaベースの設定・メタデータリポジトリサーバー「Central Dogma」において、ZooKeeperレプリケーションを有効化する際に replication.secret を明示設定しないと、サーバーが公開既知のハードコード秘密鍵にサイレントにフォールバックする。このデフォルト認証情報で組み込みZooKeeperアンサンブルに認証でき、攻撃者はレプリケーションログ全体を読み取るか、クォーラムに参加してクラスタ全体に任意のレプリケーションコマンドを実行できる

  • 修正内容 — 0.84.0 でデフォルトフォールバックを廃止し、replication.secret の明示設定を必須化
  • 対応 — centraldogma-server を 0.84.0 以降に更新。ZooKeeperレプリケーションを有効化する場合は必ず replication.secret を明示設定。ZooKeeperアンサンブルへのネットワークアクセスを信頼ホストのみに制限

3. IBM WebSphere Application Server CVE-2026-9006 — Ajax ProxyのSSRFで認証不要の内部アクセス（CVSS 7.4） HIGH

項目詳細
CVECVE-2026-9006（CVSS 3.1: 7.4 / AV:N/AC:H/PR:N/UI:N/S:U/C:H/I:H/A:N）
公表日2026-06-22（NVD公開、Tenable 新着リスト掲載）
影響バージョンIBM WebSphere Application Server 9.0 および 8.5（Ajax Proxy構成時）
修正バージョンパッチ提供済み（IBMセキュリティー速報に準拠）
脆弱性種別CWE-918 サーバーサイドリクエストフォージェリ（SSRF）
悪用状況公開PoCなし・能動的悪用の証拠なし（Nessus検出ID 321308 追加済み）
  • 概要 — IBM WebSphere Application Server 9.0/8.5 の Ajax Proxy 構成においてSSRFの脆弱性。ネットワーク上の未認証攻撃者が脆弱サーバーから内部・外部システムへ不正なリクエストを送信でき、セキュリティ制御のバイパスや本来アクセスできない機密情報へのアクセスが可能
  • 影響 — Ajax Proxyは社内ネットワーク境界で稼働することが多く、SSRF経由で内部API・メタデータサービス・クラウド内部エンドポイントへの踏み台になり得る。攻撃複雑度は高い（AC:H）だが、認証不要で機密性・完全性に高影響
  • 対応 — WebSphere 9.0/8.5 をパッチ適用版に更新。Ajax Proxyが不要なら無効化。サーバーからのアウトバウンド接続を必要な宛先のみに制限し、不審な外向きリクエストを監視

🔴 SiYuan CVE-2026-56395 / 56397 — BazaarマーケットプレースのXSS（nodeIntegration有効）経由RCE（CVSS 9.6） CRITICAL

項目詳細
CVECVE-2026-56395（CVSS 3.1: 9.6 / AV:N/AC:L/PR:N/UI:R/S:C/C:H/I:H/A:H）／CVE-2026-56397（同系）
公表日2026-06-21 22:27 JST（NVD公開）／2026-06-22 の CVE Brief で注目CVEとして取り上げ
影響バージョンSiYuan 3.6.0 以前
修正バージョン3.6.1 以降
脆弱性種別CWE-79 XSS → リモートコード実行（Electronの nodeIntegration 有効）
悪用状況公開PoCなし・能動的悪用の証拠なし（悪意あるパッケージ作者がマーケットプレース経由で配信）
  • 概要 — オープンソースのローカルノートアプリ「SiYuan（思源）」のBazaarマーケットプレースにおいて、パッケージのメタデータ（displayName・description）やREADMEのサニタイズが不十分。Electronアプリで nodeIntegration が有効な状態でコンテンツがレンダリングされるため、悪意あるパッケージ作者がHTML/JavaScriptを注入すると、ユーザーがBazaarを閲覧しただけでOSコマンドが実行され、アプリプロセス権限で完全なシステムアクセスを得られる
  • 背景 — AI/開発者向けツールの「マーケットプレース／プラグイン経由の供給連鎖攻撃」の典型パターン。SiYuanは技術者向けノートとして人気を集めており、Bazaar経由のテーマ・プラグイン閲覧が日常操作に含まれる点がリスクを高める
  • 影響 — ユーザーの閲覧操作（UI:R）を起点にローカルRCEが成立。ローカルノートは社内メモ・コードスニペット・シークレットメモを保持することが多く、乗っ取られれば端末上の機密が窃取される
  • 対応 — SiYuan を 3.6.1 以降に更新。Electronの nodeIntegration を無効化し、CSPヘッダを厳格化。Bazaar経由の未知パッケージ導入を制限し、ユーザー提供コンテンツのレンダリング前にサニタイズを徹底
