Critical Apache Shiro 3.0.0以下（Java） — 認証キャッシュ有効な LDAP レルムで任意パスワードによりログイン可（CVE-2026-129349、CVSSv3.1 9.1）

深刻度CVSSv3.1 9.1（Critical）
CVECVE-2026-129349
影響Apache Shiro 3.0.0 以下（DefaultLdapRealm／JndiLdapRealm を authenticationCachingEnabled=true で使用時のみ）
公開2026-11-15（oss-security 2026/11/14、NVD登録 11-15 10:16 UTC）
出典oss-security
  • Java の認証・認可フレームワーク Apache Shiro の DefaultLdapRealm で、認証キャッシュを有効にしていると、一度でもログインに成功したユーザーは以後 任意のパスワードでログインできてしまいます。キャッシュ済み認証は LDAP バインドを省略する一方、DefaultLdapRealm が既定で導入する AllowAllCredentialsMatcher が資格情報を無条件に受理するためです。
  • 有効なユーザー名を知る未認証の攻撃者が、そのユーザーとして認証を通過できてしまいます。対策は 3.0.1 以降への更新（AllowAllCredentialsMatcher を既定で導入しないよう修正）、または LDAP レルムの認証キャッシュを無効化（既定）するか、資格情報を検証する資格情報マッチャ（SimpleCredentialsMatcher 等）を構成することです。
  • Spring 系アプリで Shiro を LDAP 認証に用いている構成は、authenticationCachingEnabled の設定を今一度ご確認くださいませ。

深刻度CVSSv3.1 9.1（Critical）

影響Cyrus SASL 2.1.28 以下（SRP サーバ機構 plugins/srp.c）
公開NVD登録 2026-11-15 14:17 UTC
  • srp_server_mech_step2() が、クライアント公開値 A が N の倍数である場合を拒否していないため、未認証のネットワーククライアントが A=N を送って共有秘密をゼロに強制できます。
