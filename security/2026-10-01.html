Claude Code — 組織のサーバ管理設定が適用されないおそれ（CVE-2026-103012）

深刻度Low（CVE-2026-103012、CVSSv4.0 2.0）
CVECVE-2026-103012（不適切な認可・管理ポリシーの回避、GHSA-gfvf-j8jh-jxxw）
影響Claude for Enterprise は 2.0.68 以降、Claude for Work（Team）は 2.1.38（サーバ管理設定が利用可能になった版）以降
修正版Claude Code 2.1.260 以降（自動更新の場合は適用済み）
公開日NVD登録 2026-09-30 21:17 JST
  • 組織のサーバ管理設定を取得する際、Claude Code が 自身の設定に保存されたAPIキー（過去の /login や直接書き込まれたもの）を、有効な Enterprise／Team サインインより優先して選択していました。セッション自体は Enterprise／Team アカウントで認証されているにもかかわらず、設定エンドポイントがその保存済みキーを拒否すると、フォールバックとして 組織のサーバ管理ポリシー（権限のdenyルール、モデル制限、managed-only ロックなど）が適用されない状態でセッションが開始されます。
  • マシン上に以前のポリシーのキャッシュが存在する場合は、その古いコピーを適用し続け、その後のポリシー変更を受け取りません。いずれの場合も、セッションは組織アカウントとして動作し続けます。
  • 成立には当該端末へのローカルアクセスが必要で、ポリシー未適用のケースは過去に管理設定がキャッシュされていないことも条件です。MDMやファイルベースのエンドポイント管理設定は影響を受けません。
  • 報告は Tamas Voros 氏（NVIDIA AI Red Team）。同氏は Claude Code へ貢献済みであり、クラウド側の管理ポリシーが黙って無効化されうる点は、統制目的でご利用の組織にとっては看過できない挙動ですわね。
