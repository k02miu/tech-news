1. NGINX — rewrite モジュールのヒープバッファオーバーフロー（CVE-2026-9256, Critical）

項目詳細
CVECVE-2026-9256
深刻度Critical（CVSS 4.0: 9.2 / CVSS 3.1: 8.1 High）
影響NGINX Plus R32〜R37、NGINX Open Source 1.30.0〜1.31.0（ngx_http_rewrite_module）
修正NGINX Open Source 1.30.2 / 1.31.1 へアップグレード。NGINX Plus: R32 P7 / R36 P5 / 37.0.1.1
公開日2026-05-22（NVD / F5 Security Advisory）
CWECWE-122（ヒープベースバッファオーバーフロー）

NGINX および NGINX Plus の ngx_http_rewrite_module において、rewrite ディレクティブで重複キャプチャを含む正規表現（例: ^/((.*))$）と複数キャプチャを参照する置換文字列（例: $1$2）を redirect または arguments コンテキストで使用した場合に、ヒープバッファオーバーフローが発生する脆弱性が確認されました。認証されていない攻撃者が細工した HTTP リクエストを送信することで、NGINX ワーカープロセスのクラッシュ（DoS）を引き起こし、ASLR が無効または回避可能な環境では任意のコード実行に至る可能性があります。

対応:

  • NGINX Open Source: 安定版 1.30.2 またはメインライン 1.31.1 へアップグレード
  • NGINX Plus: R32 P7 / R36 P5 / 37.0.1.1 へアップグレード
  • 暫定緩和策: rewrite 定義で名前付きキャプチャ（named captures）を使用し、無名キャプチャの使用を避ける

2. GCP — 削除済み API キーが最大 23 分間有効であり続ける設計上の問題

項目詳細
分類GCP IAM 設計上の問題（CVE 未割当）
深刻度High（実運用上のリスク大）
影響すべての Google API キー（Gemini、BigQuery、Maps 等）。削除操作後も最大 23 分間（中央値 約 16 分）認証成功が継続
修正Google は当初「won't fix」としていたが、5月22日に P0 バグとして再オープン
公開日2026-05-21（Aikido Security ブログ）、2026-05-22（Google P0 再オープン）

セキュリティ企業 Aikido Security の調査により、Google Cloud コンソールで API キーを削除しても、実際の無効化までに最大 23 分（中央値約 16 分）の遅延があることが判明しました。この間、漏洩したキーを保持する攻撃者は Gemini のファイルアクセスや会話履歴、BigQuery、Google Maps などの API に継続してアクセス可能です。

Google の削除ダイアログには「このキーは API リクエストに使用できなくなります」と表示されますが、実際には即時無効化されません。一方、Service Account キーでは約 5 秒、Gemini API 専用キーでは約 1 分で無効化されることから、技術的には高速な無効化が可能であることが示唆されています。

5月22日更新: Google は当初この報告を「システムの既知の特性であり、セキュリティ問題ではない」としてクローズしていましたが、5月22日に P0（最優先）バグとして再オープンしました。

推奨対応:

  • API キー削除は最短でも 30 分かかる操作と見なし、その間は GCP コンソールの「有効な API とサービス」で API 使用状況を監視
  • 可能な限り、Service Account キーなど無効化が高速な認証方式への移行を検討
  • API キーのローテーション時は、旧キー削除後 30 分間は新キーのみを使用していることを確認

3. Python — Crawlee for Python に SSRF 脆弱性（CVE-2026-46497, High）

項目詳細
CVECVE-2026-46497
深刻度High
影響Crawlee for Python — サイトマップ由来 URL を介した Server-Side Request Forgery (SSRF)
修正設定の更新による緩和（修正バージョン情報は CVE 公開時点で未確定）
公開日2026-05-22（NVD 公開）
CWECWE-918（Server-Side Request Forgery）

Python の Web スクレイピング・クローリングフレームワーク Crawlee において、サイトマップ（sitemap）から取得した URL の検証が不十分なため、攻撃者が内部ネットワークやローカルホストへのリクエストを誘導できる SSRF 脆弱性が確認されました。

対応: 修正バージョンがリリースされ次第アップグレード。それまでの間、信頼できるサイトマップのみを処理するよう設定を制限してください。
