🟢 Django 6.1 alpha 1 リリース（5月20日）

Django 6.1 の最初のアルファ版が公開されました。本番環境向けではなく、新機能のテストとバグ報告を目的としたプレビューリリースです。正式リリースは 2026年8月を予定。

主要な新機能

  • モデルフィールド フェッチモード: QuerySet.fetch_mode() でフィールド取得動作を制御可能に。
    • FETCH_ONE（デフォルト・既存動作）: 現在のインスタンスのみフィールド取得
    • FETCH_PEERS（新機能）: 同一QuerySetの全インスタンスの不足フィールドを一括取得。N+1問題を2クエリに削減可能
    • RAISE（新機能）: 未取得フィールドアクセス時に FieldFetchBlocked 例外を発生。パフォーマンスクリティカルなコードでの意図しないクエリを防止
  • DBレベル削除オプション: ForeignKey.on_delete に DB_CASCADE, DB_SET_NULL, DB_SET_DEFAULT を追加。SQLの ON DELETE 句で処理され、Pythonレベルより高効率（pre/post_delete シグナル非発火）
  • MAILERS 設定: 複数メールバックエンドを CACHES/DATABASES と同様の方式で設定可能に。Django 7.0 で EMAIL_BACKEND を置き換え予定（後方互換性あり）
  • 管理画面の改善: フォームフィールドがラベル下に表示（アクセシビリティ向上）、エラー表示順序の改善、delete_confirmation_max_display オプション追加、アクションの location 指定対応
  • 認証: PBKDF2 イテレーション回数が 1,200,000 → 1,500,000 に増加
  • GIS: OpenLayers 10.9.0 ベースに更新、SpatiaLite で isempty ルックアップ対応、num_dimensions ルックアップ追加
  • Python互換性: Python 3.12, 3.13, 3.14 をサポート

推奨アクション: 本番環境では使用不可。開発環境・CIでのテスト参加を推奨。特に FETCH_PEERS はパフォーマンス改善のインパクトが大きく、フィードバックが求められている。

⚛️ Next.js — プレリリース（5月20日）

Next.js canary に以下の変更がマージされました。

  • nextConfig.instrumentationClientInject: クライアントサイドインストルメンテーション注入の設定オプション追加（#93785）
  • MCP compile_route ツール: AIエージェント向けルートコンパイルツール追加（#93337）
  • Nodeストリームでサーバー挿入HTMLを処理: Server Inserted HTML に Node.js ストリームを使用（#93934）
  • rootParams デフォルト有効化: ルートパラメータがデフォルトで有効に（#93863）
  • prefetch={true} と cachedNavigations のクロスパラメータリーク修正（#93940）
  • Turbopack 改善: 永続化サイズのトレースメタデータ追加、rcstrs のメモリ最適化、チャンクバージョン管理改善

推奨アクション: いずれもプレリリース（canary）のため、本番適用は要検証。rootParams のデフォルト有効化は既存プロジェクトの動作に影響する可能性あり。
