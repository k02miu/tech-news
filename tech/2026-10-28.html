🧠 Claude Code — v2.1.312

2026-10-28 05:35 JST 公開。Claude apps ゲートウェイの識別方式の拡張、クラウドセッションの操作性向上、フック実行の並行数制限の明確化などが含まれます。なお 2.1.311 は 2026-10-27 07:02 JST 公開のため、対象期間の直前となります。

🔧 新機能・改善

  • OIDC のユーザー識別クレーム設定: Claude apps ゲートウェイに oidc.user_id_claim を追加。sub 以外の id_token クレーム（Microsoft Entra ID の oid など）で利用者を識別できるようになりました。
  • クリックで送信: フルスクリーン表示中、キューに入ったメッセージ下の「to send now」ヒントをクリックすると、キー操作と同じく即時送信されます。
  • クラウドセッションのルーティン設定: クラウド実行されるルーティンの作成・編集時のモデルピッカーに effort level が追加されました。
  • クラウド環境のセットアップスクリプト編集: 色分け・行番号・コピーボタンを備えた Bash エディタを追加。
  • WebFetch エラーの説明改善: クラウドセッションで名前解決できないホストについて、許可ドメイン外の可能性を明示し、許可すべきホスト名を提示します。
  • プロンプトの effort 表示改善: タスク途中での変更が「次のメッセージまで待つ場合がある」旨を示し、該当しなくなれば注記が消えます。

🐛 主な修正・挙動変更

  • 未認識モデル名のシステムプロンプト: Bedrock / Vertex / Foundry / Mantle で、カスタムデプロイ名や推論プロファイル ARN など Claude Code が認識しないモデル名に対して短いシステムプロンプトを使用。CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 で従来動作を維持できます。
  • フックの並行実行制限: プロンプト／エージェントフックはセッションあたり最大24件（サブエージェント含む）、イベントのタイムアウトを超えて待機中のものは最大12件に制限。1秒未満の timeout は1秒として扱われます。
  • 使用量上限の文言: 5時間ウィンドウを「session limit」ではなく「5-hour limit」と表記するよう変更。
  • サブエージェントの autoCompactWindow: CLAUDE_CODE_AUTO_COMPACT_WINDOW で設定された値より下げる方向にのみ作用するよう修正（従来は効果がありませんでした）。
  • OpenTelemetry の MCP サーバー名: 公式マーケットプレイスのプラグインが宣言する固定URLリモートMCPサーバーについて、custom ではなく実際の名前を報告。
  • テレメトリ削減: claude_code.safety_event OpenTelemetry イベントの送信を停止。
  • VS Code: 使用量上限のリセットを時刻表示（「Resets at 3:10 PM」）に変更し、「5-hour limit」表記に対応。

🐙 OpenClaw — v2026.10.8

2026-10-27 20:56 JST 公開。更新処理の完遂と復旧、Gateway サービスのインストール堅牢化、会話の受信継続性、セキュリティ強化が中心のリリースです。同日 2026-10-27 11:20 JST には LTS 相当の extended-stable v2026.9.35 も公開されています。

🔧 主な変更点（v2026.10.8）

  • 更新の完遂と復旧: 更新後の Doctor が通常失敗した場合に Gateway を停止したままにせず再起動。孤児化したメンテナンスワーカーが全CLIコマンドと Gateway 起動をブロックする問題も解消。ACL ファイルシステム、Windows の pnpm オプショナル依存リンク、pnpm 10 のグローバルインストールなどでの更新中断も修正。
  • Gateway サービスのインストール: macOS では plist が削除された launchd 登録を復旧、Linux では Ubuntu 既定 umask 環境でプライベートな状態ディレクトリを作成して拒否を回避、macOS アップデータは Doctor 実行前に Gateway がデータベースを解放するのを待機。
  • 会話の受信継続: 強制終了された実行の restart-recovery フェンスを解放、Gateway 再起動後の子セッション復旧、返信ランタイムが publish できない場合の無限リトライ停止。
  • 起動・DB の耐障害性: 起動処理が閉じた SQLite リーダースコープを継承しないよう修正し、モデル・チャットメタデータ・チャネル返信の可用性を維持。エージェントDB起動時の一時的ロック競合をリトライ。
  • セキュリティ強化: exec 許可リストモードで test -v のオペランド展開に承認を要求、汎用 node invoke でブラウザプロキシコマンドを拒否、サンドボックス内の子プロセスがホストCLIバックエンドを実行できないよう制限、シークレット外向きプロキシが不信な eMudhra 証明書チェーンを拒否、Fish Audio / Gradium のエラーでAPIキーが露出しないよう修正。
  • プロバイダ／モデル継続性: Codex ターンが古いランタイムプラグインでも予算を維持、Anthropic の PDF 解析が setup-token OAuth で動作、タイムアウトした MCP セッションクローズが次ターンを壊さないよう修正。
  • extended-stable v2026.9.35: サービス管理下でのメモリ安定化（workerヒープ上限、アイドル Codex app-server の30秒退役）、更新完了率の向上、Gateway イベントループの停止防止、SQLite 3.54 のフルテキストインデックス修復などをバックポート。

🐋 Orca — v1.4.242

2026-10-27 09:09 JST 公開。メモリ使用量の削減、Claude サブエージェントへのサイドバーからのアクセス、リモートサーバーのタブ永続化が主な内容です。

🔧 新機能・改善

  • サイドバーから Claude サブエージェントを開く: サイドバーまたはダッシュボードのサブエージェント行をクリックすると、同じターミナルでトランスクリプトを表示。親をクリックすれば戻れ、閲覧中のものは目印が付きます。
  • 編集前に確認するチャット: Codex の Ask モードがワークスペース編集前に確認するようになりました（Approve for me / Full access は従来どおり）。ペアサーバー上のリモート Claude ターミナルは Chat で継続可能に。
  • エージェントの状態復元: 再開した Claude セッションが effort level と起動フラグを保持、Codex は最後に付与した権限を維持、Session History はより多くのフォルダとサーバーのチャットを検出。
  • リモートサーバーの記憶: ペアサーバーが再起動をまたいでタブを保持、閉じたタブは閉じたまま、WSL ホストは再起動ごとに再ペアリングしないよう修正、SSH 失敗時は原因を明示。
  • メモリ削減: ターミナルのアイドルCPU使用量を大幅削減、ターミナルホストのメモリ使用量と WSL 接続のメモリ消費を低減、リソースパネルが macOS の Activity Monitor と一致するよう修正。
  • コミュニティ修正: スペースを含む Windows ランチャーパス、韓国語入力、オートメーションの DST、focus-follows-mouse、タブドラッグ、Linux パッケージの不具合を修正。
