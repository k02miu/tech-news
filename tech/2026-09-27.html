🐋 Orca — v1.4.214

対象期間内に v1.4.214（2026-09-27 07:36 JST 公開）がリリースされました。今回は Jupyter ノートブック（.ipynb）のネイティブ対応が最大の目玉で、加えてネイティブチャットのコンテキスト使用量表示、ZCode のハーネス対応、プロファイル保存の SQLite 移行が入っております。

🔧 新機能・改善

  • Jupyter ノートブックをネイティブ表示: .ipynb がそのままノートブックとして描画され、セルをクリックして直接編集できます。セル実行は永続的な Jupyter カーネル上で行われ、pip がロックされている環境では .venv を自動作成し、ipykernel のセットアップ進捗も表示されます。ワークスペースのインタプリタは、ノートブックが信頼されるまで実行されません。
  • ネイティブチャットの拡充: composer にコンテキストウィンドウの使用量が表示され、送信済みメッセージにはホバーでコピーボタンが出ます。スクロールすると古い履歴が自動で読み込まれ、メッセージレールには読み込み済みでないユーザーメッセージも含めて全件が表示されます。構造化チャットは再起動後もクリーンに再開します。
  • Codex 0.157 以降が Orca 管理下のホームで正常起動: パス長（SUN_LEN）による失敗を回避し、単一のシェル環境設定で全構造化チャットを扱えるようになりました。Codex の各ジャーナル行には生成元エージェントが記録されます。
  • 子ワーク／サブエージェントの状態追跡: Codex・Claude・Pi・Grok をまたいで子ワークの状態が統合表示されます。ZCode が第一級のサポート対象ハーネスとして加わりました。
  • ターミナル・エディタ・ワークスペース: 単一ターミナルペインに明示的なクローズボタンが付き、再マウントされた SSH タブはシェルを正しく再生成します。管理下の WSL ターミナルには Orca CLI が自動で提供されます。ワークスペースのフォルダトグルは即時反映となり、AI ノートの UI も刷新されました。
  • 永続化と性能: プロファイル保存が SQLite に移行し、バックグラウンド書き込みと、ヘッドレス Orca 向けのバンドル済み Bun が導入されました。検索はバンドル済み ripgrep がローカル・WSL・SSH を担い、並行トランスクリプト読み込み・レディネスプローブ・ターミナルマーカー走査が大幅に低遅延化しています。
  • リモート／relay／ブラウザ: リージョナル rehome オペレータが新しいプロダクションセルを受け入れ、relay のドレイン時間により接続断が防止されます。ブラウザのピクセルキャプチャは必要な場合のみ待機します。
  • モバイル: OTA ページでネイティブのセーフエリア制御を獲得し、ストリーミングされるブラウザペインの扱いが滑らかになり、Android のライブ入力エコーが修正されました。ペアリング後もマシン名が保持されます。

🐛 主な修正

  • 構造化チャットの再開まわり: 再開に失敗したチャットがステータスバーに残り続けて対処法を示すようになり、Claude 自身が再開したターンを provider が再度開けるよう修正されました。境界付きテール読み込みが未適用行を飛び越えてカーソルを進める問題も解消されています。
  • エージェント状態の集計: 統計がエージェントの作業のみを数えるようになり、Grok のバックグラウンドサブエージェントが「作業中」として扱われます。OpenCode のサブエージェントの系譜解決により、子ワークがペインを乗っ取る問題が修正されました。
  • OpenCode 連携: OpenCode Go の使用量を Go API キーで読むよう修正し、rate-limit プラグインに固有の ID を付与、未確認のハンドオフを成功と報告しないようにしました。
  • フック: タイムアウトした hook は「検証不能」として報告され、そのプロセスツリーが終了されます。
  • そのほか: Windows で巨大な数値ファイル ID を読めるよう修正、不正な Base64 パディングの拒否、リモートが存在しない場合の upstream プローブ省略、PTY の EAGAIN 再試行のペーシング（停滞したリーダーがデーモンスレッドを飽和させる問題）など。
