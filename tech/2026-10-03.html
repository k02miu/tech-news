🧠 Claude Code — v2.1.288

2026-10-03 05:34 JST 公開。プラグイン／mod 向けの選択範囲 API、クラウドセッション向けの組み込み gh api、Ctrl+C で消したプロンプトの復元などが入り、あわせて --resume 周りやプラグイン、権限チェックに関する多数の修正が含まれる大型リリースです。

🔧 新機能・改善

  • mod 向け $.ui.selection(): フルスクリーンで最後に選択したテキストを取得できます。選択範囲が1つのトランスクリプト行に収まる場合はその行も返します。
  • クラウドセッションの組み込み gh api: GitHub CLI を含まないイメージでも利用可能になりました。ファイル名・jq フィルタ・GitHub のエラーに含まれる制御文字がターミナルへ送出される不具合も修正されています。
  • Ctrl+C で消したプロンプトの復元: 空のプロンプトで ↑ を押すと、貼り付けたテキストや画像も含めて下書きが戻ります。
  • MCP の OAuth スコープ追加要求: ツール呼び出し中に MCP サーバーが追加スコープを求めた際、再認証を促すプロンプトが表示されるようになりました。
  • /code-review の --max-findings <n>|all: 通常の上限より多く／少なく指摘を報告できます。--max-findings default を渡すまで選択が再利用されます。
  • agents ビューの操作性: Ctrl+F でセッション名検索、Alt+↑/↓ でグループ間移動ができるようになりました（リネームとあわせて keybindings.json で再割り当て可能）。
  • 画面読み上げモード: プラン承認時に新しい権限モードを読み上げます（Shift+Tab 使用時も含む）。削除した単語などの短い通知は、次のキー入力か画面上の変化まで表示され続けるようになりました。
  • auto mode の改善: 会話が長くなりクライアント側の安全分類器で審査できなくなった場合、ツール呼び出しごとにプロンプトを出す／失敗させるのではなくコンパクションするようになりました。
  • その他の改善: 新規会話の最初のターンが alwaysLoad: false の stdio MCP サーバーを待たなくなりました。/usage-credits のメッセージ、artifact データベースの容量上限エラー、Bash 権限プロンプトの理由表示も改善されています。

🐛 主な修正

  • 応答途中の API タイムアウト: 非対話セッションとサブエージェントが部分応答から継続できるようになり、thinking のみの応答は再試行されます。
  • 長い会話の「Prompt is too long」: 直前の応答がトークン使用量ゼロを報告した場合に自動コンパクションへ移行せず失敗する問題を修正しました。
  • --resume 関連: コンパクションで復元した直後のファイル等のコンテキストが落ちる問題、ターンの最後の応答が保存されず次回の --resume で未回答に見える問題、読み込み中に同一セッションがファイルを書き換えると途中までのトランスクリプトを読む問題を修正。2.1.286 以前に開始した会話を再開すると以前の thinking が失われる問題も修正されました。
  • 危険な rm の保護強化: bash -c / sh -c のスクリプト内で / やホームディレクトリへの rm が、bypassPermissions モードやシェルの許可ルール下で確認なしに実行される問題を修正しました（anthropics/claude-code#96300）。
  • structured outputs 非対応環境: Mantle 上や structured outputs を拒否するゲートウェイ配下で、セッションタイトル・メモリ想起・プロンプトフックが失敗する問題を修正。CLAUDE_CODE_DISABLE_STRUCTURED_OUTPUTS で無効化も可能です。
  • プラグイン: git-subdir インストールが古い git（2.39 未満、Ubuntu 22.04 の 2.34 など）で失敗／不完全にキャッシュされる問題、リロードや無効化で実行中のタイマー・読み取りがあるとバックグラウンドセッションが終了する問題、Code 要素に解析不能な diff があるとペインが空になる問題などを修正しました。
  • LSP ツールのハング: 動的ケイパビリティ登録を使う言語サーバーや応答停止時に無限に待ち続ける問題を修正し、60秒（サーバー単位の requestTimeout）でタイムアウトするようにしました。
  • MCP ツール呼び出しの二重実行: リモートサーバーの結果が 16MB 超、または解析できなかった場合に二重実行されることがある問題を修正しました。
  • フック: マッチング失敗やツール入力の JSON シリアライズ失敗時に PreToolUse / PermissionRequest フックがスキップされていた問題を修正（該当呼び出しはブロックされます）。バックグラウンドエージェント実行中に idle_prompt 通知フックが発火する問題も修正されました（#93672）。
  • マネージド環境のログイン: 資格情報を安全なストレージへ保存できなかった場合でも「Login successful」と表示していた問題を修正し、失敗表示と再試行を提示するようになりました（#73861）。
  • 自動更新: プラットフォームネイティブのバイナリ取得に失敗しプレースホルダの claude スタブのみが入った状態でも成功と報告していた npm 側の自動更新を修正しました。
  • クラウド／Remote Control: 再起動後に組織の強制モデル一覧が拒否するモデルを復元する問題、まだ接続中／別プロセスが再アタッチ直後のセッションを Remote Control のクリーンアップがアーカイブする問題、5分間未応答の WebFetch 権限プロンプト後も「入力待ち」のままになる Cowork クラウドセッションの問題を修正しました。
  • その他: 非常に多くの Agent(...) を持つエージェント起動時の停滞、Claude 3 Opus / Sonnet で PDF 投入後の全ターン失敗、Windows 再起動後のキーボード不能、画面読み上げモードの /permissions の番号入力などを修正しました。

🐋 Orca — v1.4.219

2026-10-03 05:59 JST 公開。9月30日のデイリービルドに main からの修正をピックしたパッチリリースです。Codex のターミナル共有サーバー問題への警告と修復、エージェント起動時のフォルダ信頼の事前応答、ネイティブチャットの操作性向上が中心です。

🔧 新機能・改善

  • Codex ターミナルの共有サーバー警告と修復: Codex タブが他のタブと1つのバックグラウンドサーバーを共有すると、タブ上部に通知が表示されます。そのサーバーでは1つのタブを閉じると他が終了し、エージェントのステータスも不正確になることがあります。通知の Fix で共有を解除でき、実行されるコマンドも表示されます。更新前に開いていたターミナルでは新しいターミナルを開く案内が出ます。プレーンな fish タブで codex を実行すると、zsh / bash と同様に専用サーバーで動くようになりました。
  • Codex 設定の破損防止: ターミナルを開く際に ~/.codex から Orca のステータスフックが消える問題、フォルダの trust エントリが config.toml に二重書き込みされて全 codex コマンドが動かなくなる問題を修正し、既に書き込まれた重複もクリーンアップします。バックグラウンドの Codex 使用量チェックが Codex の更新プロンプトで「Update now」を押して壊す問題も修正されました。
  • エージェント起動時のフォルダ信頼: Orca が Claude Code、Codex、Cursor、Copilot、Qoder、Antigravity をフォルダ内で起動する際、「このフォルダを信頼しますか？」に事前に回答するようになりました。オーケストレーションのワーカー、自動化、スマートフォンから起動したエージェントがこのプロンプトで止まらなくなります（設定 → Agents → 「Trust the folder when Orca starts an agent」で無効化可能）。
  • エージェントステータスの修正: OpenCode 2 のペインが複数あっても、各ペインが自身の Working / Done を表示します。Windows で Claude Code が Windows PowerShell 5.1 のフックを実行する場合のステータスが復旧し、Codex がタブ名を変えてもサイドバーの行が実行中は残り、起動直後の Hermes はビジーではなく準備完了として表示されます。
  • ネイティブチャット（実験的）: エージェント実行中に送ったメッセージが、デスクトップでもスマートフォンでも入力欄の上のカードとして待機します。Steer で実行中のターンへ送る、編集、削除が可能で、それ以外はターン終了時に送信されます。サブエージェントの作業は会話に混ざらず専用セクションに表示され、/compact は独立した行になります。未完了の /clear がチャットをロックする問題や、Stop が遅い／「Cancellation was not confirmed」と誤表示する問題も解消しました。
  • オーケストレーション: 会話のコンパクション後にワーカーの完了報告が拒否される問題を修正し、Orca に一時的に到達できない場合は約2分間再試行するようになりました。worker-abandon はスタックしたワーカーを毎回確実に解決します。
  • ファイルとエディタ: 保存した無題ノートがタブを閉じても削除されなくなり、リッチ Markdown エディタのクリックで先頭へジャンプする問題、開いているファイルがシステムのライト／ダークモードに追随しない問題を修正。スパースチェックアウトでは作業フォルダを起点にファイルエクスプローラを開きます。
  • ターミナル: download (1).png のようにファイル名に括弧や空白を含む画像もエージェントへ添付できるようになりました。スキップされた場合の理由表示、タブが多いときの現在タブの可視性、Codex や Claude Code の起動が遅い／バックグラウンドの場合の色表示も改善しています。
  • Linux / Windows: Hyprland・sway・river・niri で、キーリングが動作・解錠されている場合は保存済みの API キーとトークンを暗号化します。暗号化されずに保存された資格情報があると設定に警告が表示されます。Windows の orca コマンドはネイティブプログラムになり、ウイルス対策による削除を回避し、Visual C++ 再頒布可能パッケージなしで動作します。
