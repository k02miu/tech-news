🧠 Claude Code — v2.1.289

2026-10-04 08:19 JST 公開。プラグイン／mod まわりの不具合修正が中心のリリースで、マネージド環境やサンドボックス下での deny / ask ルールのすり抜け、シンボリックリンク経由の Read 拒否ルールの適用漏れ、組織管理 MCP サーバーの説明書き換えなど、セキュリティ境界に関わる修正が複数含まれています。

🔧 新機能・改善

  • チームメイト向け agent.spawn: プラグインのフックイベントをまたいで1つのエージェント ID を扱えるようになり、$.agent.list() にアイドル状態と待機状態が追加されました。
  • プラグインコードペインの大ファイル表示: ハイライト表示を最終幅で一度だけレイアウトするようにし、大きなファイルを開く速度が改善しました。
  • mod 描画失敗時の表示改善: mod のバンドまたはペインが描画に失敗した際、mod 名を明示し「何も描画されなかった」ことを伝える行を改善しました。
  • 右寄せコンテンツの余白: mod のペイン／バンドの右寄せコンテンツが閉じマークや [-] の下に描画されないよう、ターミナル端から1列を確保するようになりました。

🐛 主な修正

  • 複合シェルコマンドの deny / ask ルール（マネージド環境）: ネストされた部分に対する deny / ask ルールが、ユーザーインストールの mod の承認によって上書きされてしまう問題を修正しました。
  • 環境変数プレフィックス越しの Bash ルールすり抜け: 展開値を持つ環境変数プレフィックス付きのコマンド（例: TZ="$HOME" rm -rf build）が、サンドボックスの自動許可時に deny / ask ルールを回避してしまう問題を修正しました。コマンド直前に裸の変数代入がある場合にルールがスキップされる問題も修正されています。
  • シンボリックリンク経由の Read 拒否ルール: IDE から @メンション・変更・選択されたファイル（シンボリックリンク経由）に Read の deny ルールが適用されない問題を修正しました。
  • 組織管理 MCP のサインインツール保護: ユーザーインストールのプラグインが、組織が管理する MCP サーバーのサインインツールの説明を書き換えられてしまう問題を修正しました。
  • ターミナルのフリーズ: 閉じられていない <script> タグを多数含む短いコードブロックや、深くネストした ${ 置換でターミナルがフリーズする問題を修正しました。公開された artifact ページで読者のブラウザタブがフリーズ／クラッシュする問題もあわせて修正されています。
  • [VSCode] サインアウト頻発の revert: claude auth status に対する 2.1.288 の変更（サインアウトが頻発する可能性があったもの）を巻き戻しました。
  • プラグイン一覧の古いコピー: ローカルフォルダの marketplace からインストールしたプラグインについて plugin list / plugin eval / plugin update が古いコピーを表示する問題、およびシンボリックリンクされた --plugin-dir のホットリロードを修正しました。
  • アップグレード直後の mod 未読込: アップグレード後の最初のセッションでインストール済み mod が読み込まれない問題を修正しました。
  • プラグイン描画失敗でのセッション終了: プラグインの on-screen ハンドラが非同期に throw した場合、高さのないリージョンが成長し続けた場合、mod の ui.render が書いた値で行の描画が throw した場合などに、セッションがインターフェースエラーで終了する問題を修正しました。
  • claude plugin validate: フォルダに marketplace マニフェストも含まれる場合にプラグインをスキップしてしまう問題を修正しました。
  • その他: 不明なボーダースタイルの Box を描画した際の起動時フリーズ／強制終了、フルスクリーンでバックグラウンドタスクダイアログを開いている間にプラグインの行が古い表示になる問題、タブ・C1 制御文字・CRLF を含むテキストが下の行に描画される問題などを修正しました。

🐙 OpenClaw — v2026.9.8

2026-10-03 12:21 JST 公開。43 pull requests・12 direct commits・8 contributors のリリースで、OpenAI プロバイダ経由の GPT-6.1 Sol 対応、Control UI と更新修復の不具合修正、Windows 起動問題への対処が中心です。

🔧 新機能・改善

  • GPT-6.1 Sol の追加: アクセス権のあるアカウント向けに、OpenAI プロバイダ経由のモデル選択肢として追加されました。
  • Control UI のタブ継続性: 更新・再起動をまたいで開いたままのタブが、保持されているそのバージョンのファイルを待ってビューの読み込みを継続できるようになりました。保持は最大3世代・96 MiB に制限されます。
  • キーボードによる誤割り当ての修正: Control UI でキーボード操作により意図しないセッションが割り当てられる問題を修正しました。
  • silent-reply ヘルプの明確化: 既存の20ロケールで、silent-reply 設定がグループ向けであり、直接チャットと内部セッションには返信が必要である旨を説明するようになりました（挙動の変更はありません）。

🐛 主な修正

  • 更新修復がプラグイン選択を保持: 互換性のないプラグインが存在しても allowlist と有効エントリを維持し、パッケージ変更がなくても Doctor の保留中の移行確認を完了できるようになりました。完了レシートは更新履歴を書き換えずに古い警告を抑制します。
  • Windows 起動問題: コンパイルキャッシュのパスを短縮し、長すぎるパスを警告付きで無効化しました。子プロセスも安全でない継承キャッシュパスを回避します。
  • Gateway の所有権: 直接起動およびコンテナのオンボーディングで共有状態の排他的所有を強制し、競合する Gateway の起動を防止します。一時的な SQLite 競合には、メンテナンスリースが有効な間に限定的なリトライを行います。
  • 委譲結果の一度きりの配信: 内部セッション（サブエージェントや Control UI セッション）が NO_REPLY で完了するのではなく、結果を返すか作業を継続するようになりました。sessions_send は要求元の ID を維持しつつ、その場で確定した返信を返すか後で一度だけ配信します。
  • Anthropic バックグラウンド結果の保持: Bash・agent・workflow の結果が消費されるまでターンに紐付くようになりました（失敗は引き続きターンを終了させます）。
  • セッション修復: 深い所有権チェーンを再帰スタックオーバーフローなしでたどり、トランスクリプトの所有権と履歴を保持します。
  • セキュリティと信頼: ローカル TLS ヘルスプローブが管理プロキシポリシーを保持し、接続ごとに設定された証明書フィンガープリントを検証するようになりました。ログの秘匿は繰り返し処理を避け、Bun 上で見落としていた長い難読化代入を修正しています。
  • 互換性の変更: 自動ピアのやり取りとターゲット告知ターンが廃止されました。カスタムワークフローは明示的なフォローアップまたはメッセージツール呼び出しが必要です。silentReply.internal / silentReply.direct は Doctor が削除しますが、silentReply.group と無関係な設定は保持されます。
  • Telegram 移行: Doctor は検証済みの空の退役 version-1 バインドファイルのみをアーカイブし、非空・不確実なファイルはオペレータの確認用に残します。書き込み権限を持つキュー済みプレビューは送信前に権限を再確認します。
