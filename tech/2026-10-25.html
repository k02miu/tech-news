🐙 v2026.10.7（通常ライン）

🔧 新機能・改善

  • Google モデル: Gemini 4 Argon のサポートが追加されました。
  • セッション復旧の再生安全性: 中断されたセッションが復旧の由来（provenance）と未完了のツール結果を保持するようになり、停止した会話は次のメッセージを受け付ける前に終端の復旧残骸を片付けます。
  • アップデートの有効化と復旧: 検証済みのアクティベーションが、その後のメンテナンスや台帳（ledger）エラーを経ても成功状態を保ちます。中断されたパッケージ更新は安全に再開し、有効化後の Doctor 待機は上限付きとなり、古いレシートが正当な修復を拒否できなくなりました。
  • データベースとワーカーの継続性: メンテナンス拒否時もピアの読み取り・借用を維持し、互換性のない保持中のエージェント DB は隔離され、空のトランスクリプト削除は不要なアーカイブ実体化をスキップします。
  • バックアップと状態の耐久性: スナップショットが対応する旧形式の exec 承認ポリシーを保持し、中断された R2 検証・リストアが安全に再開。切り詰められた書き込みの間も config 監視は last-known-good スナップショットを保ちます。
  • オペレーター制御の継続性: セッション期限切れ後もネイティブの computer control が復旧し、後から接続した GitHub オペレーターが PR を公開できるようになりました。
  • プロバイダ／プラグインの継続性: モデル更新、設定済みアカウントの準備確認、GPT-5.6 のツールターン、OpenRouter のオンボーディング、プラグインの増分ロードが、妥当なセットアップを拒否せず現状の状態を保持します。

🐛 主な修正

  • macOS のオンボーディング: 新規プロファイルでも Gateway を起動し、自動セットアップを完了できるようになりました。
  • Gateway のログ: 削除済み・古い一時ログディレクトリが日付切り替え時に Gateway を CPU 全開で固まらせる問題が修正されました（#130807）。
  • 更新ガイダンス: パッケージマネージャが無い場合に無関係な DB 修復案内を出さず、更新成功後は陳腐化した警告を消すようになりました。
  • Control UI のキュー状態: キューのコマンドが消費された後に slash-steer チップがクリアされます。

🐙 v2026.9.34（extended-stable / LTS 相当）

Gateway 専用の extended-stable リリースです。2026年9月末時点の OpenClaw に、重要なセキュリティ更新・信頼性・性能の修正と新しいモデル対応を載せた位置づけで、公開時点の通常ライン最新版は 2026.10.6 でした。

  • エージェントのファイル編集がより安全に: apply_patch がワークスペースを変更する前に順序付きエンベロープを検証するようになり、後続の不正なハンクが先行操作で変更したファイルを削除できなくなりました。
  • マネージド更新の信頼性向上: アプリ所有の更新が core と並んで公式プラグインを収束させ、修復のための診断情報を保持します（#174120 を修正）。
  • Memory Wiki のデータ安全性: OKF コンセプトの再インポート時に人手で書かれたノートが保持されます（#175700 を修正）。
  • モデル起動・選択の信頼性: Gateway 起動がモデル更新時の所有権差し替えをまたいで生存し、カタログ準備が有効なプライマリモデルの設定済みアカウントピンを尊重します（#178502 を修正）。
  • Gateway と連携の安定性: ログローテーションが削除済み /tmp で空回りせず、Buzz relay のクローズが認証中に Gateway を終了させなくなり、OpenRouter のオンボーディングが有効な資格情報を受け付けます。
  • プラグインフックの復旧: before_tool_call フックが openclaw agent exec 配下でも実行されるようになりました（#158824 を修正）。
  • セキュリティ: 脆弱な Node ランタイムを明確な案内付きで拒否するため、Node >=24.22.1 <25 || >=26.12.1 をインストール・更新・Docker イメージ・macOS アプリのランタイムチェックで要求します。あわせて zod（GHSA-mrhx-c7xc-m3w5）、body-parser ほかの本番依存アドバイザリが修正されました。

🐋 Orca — v1.4.239

対象期間内に1件のリリースが確認されました。v1.4.239（2026-10-24 16:10 JST 公開）です。同日に v1.4.238 も公開されており、本版では「エージェントスキルの導入」「プロジェクト単位のブラウザプロファイル」「チャットとターミナルの行き来」「SSH 復旧」「スマホ操作」が主な柱となっています。

🔧 新機能・改善

  • スキルを使う場所でそのまま導入: セットアップ画面からワンクリックで Orca のスキルをインストールでき、ペアリング済みサーバや SSH ホストへは Orca 自身のインストーラで導入・更新できます（従来の npx skills 依存を解消）。
  • プロジェクトに合わせたブラウザ: 新規タブのプロファイルを「共有 / リポジトリ単位 / ワークスペース単位」から選べます（設定 → Browser → Profile for new tabs、既定は Shared）。Chrome 風のページコンテキストメニューと DevTools ショートカットも追加されました。
  • エージェント対話の流動性: 現在のチャットの隣に新しいチャットを分割して開け、ペインヘッダからターミナルエージェントへ継続できます。キュー済みメッセージと複数画像の添付が保持されます。
  • 編集の安全性と静かなバックグラウンド動作: 共有ファイルのビューが undo / discard 後も最新に保たれ、非 UTF-8 ファイルは変換前に確認を求めます。ファイル監視は遅延から復帰し、監視対象の無関係なファイルが削減されました。
  • リモート作業の復帰路: 設定から stale lock に陥った対応済みマネージド SSH サーバを復旧でき、パスワードサインイン後にターミナルが復元されます。ペアリング済みサーバの SSH アクセスリンクは再起動をまたいで保持されます。
  • スマホからの操作性向上: 通知タップで送信元エージェントを開き、エージェントチャットのタブから音声入力を開始でき、ターミナルのコピー（Claude Code の /btw コピーを含む OSC 52 書き込み）がスマホのクリップボードに届きます。Android ではスクロール時にキーボードが退きます。
  • 日常的な仕上げ: 韓国語入力の改善、ベンガル語ほかインド系文字のターミナル描画、翻訳カタログの拡充、Jira のユーザーピッカー、PR コメントのリンクからエディタへ直接ジャンプ。

⚠️ 互換性・アップグレードの注意

  • ブラウザプロファイル: 既定は従来どおり Shared で、リポジトリ単位・ワークスペース単位の指定は新規タブに適用されます。ペアリング済みサーバのページはサーバ自身のプロファイルを使います。
  • ネイティブチャット（実験的）: 最新のチャット・起動修正のため、ペアリング済みホストと SSH ホストも Orca と同時に更新してください。チャットの可用性はターミナル CLI とは別にチャットランタイムを検査するようになりました。
  • SSH 復旧: 「Recover server…」は stale lock 拒否を報告する対応済みマネージド Linux ホスト向けです。ロックを確認し、同じホームを共有する他マシンが Orca を動かしていないことの確認を求めます。スマホからはデスクトップ設定へ誘導されます。
  • 実験的機能: コネクタ関連は既定無効の experimentalConnectors フラグの背後にあり、レイアウト所有権の下地も無効のままです。空グループの起動アクションと子ワークスペースの状態トグルはリリース前に revert されました。
