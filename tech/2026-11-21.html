🧠 Claude Code — v2.1.330

2026-11-21 07:38 JST に v2.1.330 が公開されました。Anthropic の Enterprise Admin Console で管理される組織へのサインイン対応、セルフホストランナーの運用性向上、VS Code 拡張の設定追加が中心です。日本時間の早朝公開のため、対象期間内のリリースは本バージョンのみとなります。

🔧 新機能・改善

  • 組織サインイン: Anthropic の Enterprise Admin Console で管理される組織へサインイン可能に。claude auth login の後、組織の設定が適用され、そのクラウドプロバイダーまたはゲートウェイが使用されます。
  • easel（組み込みモッド）: 依頼時にグラフを描画する組み込み機能を追加。MCP のメトリクス結果の下にも表示されます。Pro / Max、および利用可能な場合は Team / Enterprise の macOS・Linux で提供され、/config で自動描画を無効化できます。
  • サインインリンクの完全表示: 短縮リンクがエラーになる場合やスクリプトが値を読み取る場合に、完全なリンクを出力する CLAUDE_CODE_FULL_SIGN_IN_LINK=1 を追加。
  • セルフホストランナー: リポジトリ内の任意フォルダを作業開始地点にする --start-dir / SELF_HOSTED_RUNNER_START_DIR を追加。あわせて、プラグインマーケットプレイスの取得失敗や Anthropic 管理 git によるプラグインリポジトリの拒否を通知するようになりました。
  • プラグイン CLI の JSON 出力: claude plugin install --json の結果に commandPrinted（インストールコマンドが stderr に書き込んだ場合 true）と commandFailed（異常終了・kill・タイムアウト時）を追加。
  • ランナーのメトリクス: claude_code_self_hosted_runner_order_to_registered_seconds と claude_code_self_hosted_runner_order_to_first_session_seconds を /metrics に追加し、作業指示から登録・セッション引き渡しまでの遅延を計測可能に。
  • [VSCode]: 会話の最後の応答以降を分岐する /fork、実行中ワークフローをエージェントマップで開く /workflows、Escape で停止しない claudeCode.escapeStopsClaude、メッセージを固定しない claudeCode.pinPrompt、コンテキスト表示の閾値 claudeCode.contextUsageThreshold を追加。「Open in Side Bar」に prompt 引数、セッショングループのメニューに Move up / Move down を追加しました。

🐛 主な変更・修正

  • max_tokens 自動リトライの復活: v2.1.329 で削除された、max_tokens がモデルまたはゲートウェイの上限を超えた際の自動リトライが復元されました。
  • スケジュールタスクの期間延長: セッションが継続している間、定期スケジュールタスクと /loop の実行期間が 7 日から最大 30 日に延長され、終了時期も明示されるようになりました（本リリース以前に作成したタスクは 7 日のまま）。
  • rm の承認強化: ルート、ホーム、トップレベルフォルダ、作業フォルダを対象とする rm コマンドが承認を求めるようになり、応答できる人がいない場合は拒否されます。
  • MCP 拒否の範囲: deniedMcpServers の名前指定は、その名前の claude.ai コネクタのみを隠す挙動に変更。同 URL の他コネクタも遮断するには正確な URL を指定します。
  • モデル名の扱い: 「sonnet」「haiku」を含む未認識のモデル名は他と同様に短いシステムプロンプトを使用。CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 で全モデルに完全版を適用できます。
  • モデル設定の継承: model 設定付きスキル（context: fork を除く）は、サブエージェント・フォーク・コンパクション・/recap をセッションのモデルのまま実行。サブエージェントのフォールバックも引き継がれ、そのサブエージェントが起動するエージェントはフォールバックの Bedrock リージョンを使用します。
  • トークン消費の削減: Claude apps gateway にサインインしたターミナルセッションでは、サブエージェントの進捗サマリーが会話全体ではなく短いメモから生成されるようになりました。
  • セルフホストランナー: spawn-runner フックが並行起動可能に（--hook-concurrency、既定 4）。Bash コマンドは不要な場合にファイル差分を省略し、チェックアウトフックがステータス 108 で終了した際は他ランナーを試さず即座に開始を中止します。

☁️ AWS

  • AWS Lambda が Python 3.15 に対応: Event Functions で一般提供、Web Functions ではパブリックプレビュー。Web Functions としては初の Python ランタイムで、これまで Node.js のみだった Web アプリ・API 構築が Python でも可能になりました。
  • AWS Lambda が Node.js 26 に対応: マネージドランタイムおよびベースコンテナイメージ（Event Functions のみ）として利用可能。Node.js 26 は最新の LTS リリースです。
  • Amazon EC2 T9g インスタンス（Graviton5）が一般提供: 低コストなバースト可能インスタンス。第 6 世代 Nitro カードを採用し、前世代 T4g 比で最大 45% 優れた価格性能比を実現するとのことです。
  • Amazon S3 の読み取りレートが最大 2 倍に: 汎用バケットで 1 秒あたり 5,500 から少なくとも 11,000 GET/HEAD リクエストに対応。プレフィックスを分散させるとスループットを最大化できます。
  • Amazon S3 Vectors のメタデータ上限を拡大: ベクトルあたりのフィルタ可能メタデータが 2 KB から 40 KB に。RAG やエージェント、セマンティック検索で絞り込み条件を増やせます。
  • Amazon EventBridge Custom event bus が Webhook Events に対応: SaaS や AI エージェント、独自連携から HTTPS でイベントを送信可能に。受信用の API エンドポイントやコンピュートを自前で運用する必要がなくなります。
  • Amazon Aurora MySQL 8.4.12 が一般提供: セキュリティ強化とバグ修正を含みます。既知の CVE 修正のためにもアップグレードが推奨されています。
  • Amazon CloudWatch の PromQL クエリ期間を 30 日に拡大: OpenTelemetry メトリクスに対する PromQL クエリが 7 日から 30 日に延長され、30 日ローリングの SLO を単一リクエストで評価できます。

☁️ Google Cloud
