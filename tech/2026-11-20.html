🧠 Claude Code — v2.1.329 / v2.1.328

対象期間内に 2 つのバージョンが公開されました。v2.1.328（2026-11-19 10:20 JST 公開）と v2.1.329（2026-11-20 07:20 JST 公開）です。CI や自動化に影響する変更（/code-review の判定基準、スケジュールタスクの再設定、Code Mode のフック挙動）が含まれております。

🔧 新機能・改善（v2.1.329）

  • フックの可視化: フォルダのフックがどこで宣言されているかを示す信頼ダイアログの警告を追加。Claude Desktop など非対話ホストでは、管理設定のフック読み込み失敗時に会話内で警告を表示します。
  • /tasks の拡張: 現在のセッションのスケジュールタスク、/loop の wakeup、ゴール、会話のフォークを一覧に表示。x で確認のうえ1件ずつ停止できます。ヘッダーとフッターのバックグラウンド件数は、シェル・モニタ・MCP 呼び出し・エージェント・ワークフロー・スケジュールタスクをまとめた単一の数値に統一されました。
  • /mcp の診断性向上: リモート HTTP MCP サーバーが接続を拒否した際の JSON-RPC エラーメッセージを「Server message」行として表示。
  • マーケットプレイス更新の可視化: /status に「Marketplace auto-update」行を追加し、自動更新されない管理対象マーケットプレイスとその理由を明示。
  • Code Mode と OpenTelemetry の併用: テレメトリのイベント・メトリクスを有効にしたまま Code Mode を有効化可能に。スクリプト内の各ツール呼び出しがイベントを送信します（トレーシング有効時は引き続き無効）。
  • [VSCode]: 信頼プロンプトを拒否した後、メッセージボックス上に「Review trust」リンクを表示し、ウィンドウを再読み込みせずにプロンプトを再表示できます。

🔧 新機能・改善（v2.1.328）

  • auto モードの適用拡大: Amazon Bedrock、Google Cloud の Agent Platform、Microsoft Foundry、Claude apps gateway 上の Opus 4.6 / Sonnet 4.6 でも auto モードが利用可能に。権限モード未指定の対話セッションは auto モードで開始されます。
  • mcp_tool フックの "onFailure": "block": command / HTTP フックと同様に、MCP ツールフックの呼び出し失敗時にアクションをブロックできます。
  • CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME: フックが保留したツール呼び出しを claude -p --resume / --continue で実行させないための環境変数を追加。
  • OpenTelemetry の取りこぼし警告: エクスポータにエンドポイントが未設定でデータが失われる恐れがある場合、/status と claude doctor で通知します。
  • セルフホストランナー: --repository-folder、--hook-label、--metadata key=value を追加。オーケストレーターの /metrics にはキュー待ち時間の理由別メトリクスと、ランナー起動を断念した回数のメトリクスを追加しました。

🐛 主な変更・修正

  • /code-review の判定基準変更: 対象未指定時は既定ブランチとの差分全体をレビューし、多コミットブランチで diff を失う不具合も修正。多くのモデルではバグと CLAUDE.md 違反のみを報告し、各指摘を Important / Pre-existing / Nit で分類、サマリー末尾に修正案を提示するようになりました（再利用性・簡素化の指摘は /simplify に分離）。gh pr diff が失敗した場合はレビューせず停止します。
  • スケジュールタスクの移行: 新しくサインインしたセッションでは、旧バージョンで保存されたタスクの多くが再設定を要します（自セッションの --resume では引き続き実行可能）。「Exit and stop tasks」はセッションのスケジュールタスクを終了させ、resume 時に再実行されません。
  • auto モードの高速化: 大規模リポジトリでの待ち時間を減らすため git status の実行頻度を低減。変更を破棄しうる git コマンドは、作業ツリー確認までブロックされる場合があります。
  • Code Mode の安全性: PreToolUse フックのエラーでスクリプトのツール呼び出しを拒否しない挙動に変更（拒否が必要な場合は "onFailure": "block" を設定）。256 MiB を超える行範囲の読み取りはメモリ枯渇防止のため拒否されます。
  • macOS の computer use: 新しい安全規則を適用し、一部の操作は拒否、一部アプリはアクセス範囲を縮小。起動が 30 秒で完了しないアプリは諦めるようになりました。
  • 2.1.326 の自動リトライを撤回: max_tokens エラーで示された上限への自動リトライを削除。出力トークンが少ないモデルをゲートウェイ越しに使う場合は CLAUDE_CODE_MAX_OUTPUT_TOKENS を設定してください。
  • その他: Gateway 起動時に access_control.allow_cidrs が空である旨を毎回通知（公開インターネットへの露出禁止を明示）、チームメイトのペインを /bin/sh 経由で起動、/bug は送信前に Yes/No を確認、サブエージェントは既定で自身のサブエージェントを待機、サンドボックス起動失敗時の報告方法を変更。

🐙 OpenClaw — v2026.11.6 / v2026.11.10-beta.1

  • 会話の耐障害性: 設定編集をまたいでもサブエージェントとバックグラウンドターンが継続し、Gateway 再起動で送信が中断された場合も最終回答を配信。
  • Gateway の軽量化: 起動時のメモリ負荷と常駐メモリを削減（制約の厳しいホスト向け）。未使用のローカル認証情報ランタイムを遅延読み込みし、プラグインのツール探索が Gateway をブロックしないよう改善。

🔧 v2026.11.10-beta.1（ベータ版）

  • エージェントテンプレート: ClawHub パッケージからエージェントを直接追加可能に。単一の CLAW.md マニフェストと同梱スキルフォルダをネイティブの信頼フローで検証します。
  • OpenClaw ID: ID トンネル経由でノードを接続し、Access から承認。オーナー端末を自身の ID に紐付けられます。
  • ブラウザハンドオフ: エージェントを停止せずに Browser パネルからブラウザを直接引き継ぎ。
  • チャット操作: 実行を止めずに保留中のステアリングメッセージを送信、キュー済みメッセージの編集、アプリ再起動をまたいだ下書き保持に対応。
  • 更新と状態移行: 自動更新スケジュールの設定と、受信リリース自身による更新前リハーサル。Gateway 状態の移行は稼働中ストアを直接書き換えず、起動時に copy-and-swap で実施。
  • 永続実行: macOS で Gateway 再起動をまたいでバックグラウンドコマンドを継続。
