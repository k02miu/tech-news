🤖 Hermes Agent — v0.18.0「The Judgment Release」(v2026.7.1)

対象期間内に、Nous Research から Hermes Agent v0.18.0「The Judgment Release」（v2026.7.1、公開 2026-07-01、GitHub Atom エントリの updated は 2026-07-01T20:14:16Z = 2026-07-02 05:14:16 JST）が公開されました。v0.17.0 から増分で 約1,720コミット・998マージPR・2,215ファイル変更・約251,000行追加・約41,000行削除・949件のissueクローズ・370名以上のコミュニティ貢献者を数える大規模リリースです。

🎯 ヘッドライン: P0 / P1 の完全撲滅

本リリースの目玉は、リポジトリ全体の P0（critical）と P1（high）の issue・PR を100%クローズしたことです。約1.5週にわたり優先バックログを昼夜で削り、約692件の最高優先度項目（P0: issue 3件 + PR 8件、P1: issue 493件 + PR 188件）を12日間で解決。最後に落ちたクラスタは interrupt-protected-compression の sibling-fork バグ（issue #56391 / fix #56416）。今後 P0 / P1 を ゼロ で維持する方针를明示しています。

✨ 新機能・改善（主要ハイライト）

  • Mixture-of-Agents (MoA) が選択可能な第一級モデルに: 従来の "mode から model へ"。名前付き MoA プリセットが moa プロバイダ配下で Claude / GPT / Grok と並んでモデルピッカー（CLI・TUI・デスクトップ・gateway の全サーフェス）に表示され、1つの選択で ensemble にルーティングされる (#46081, #53548, #53561)
  • 各参照モデルの推理内容をラベル付きブロックで可視化 + アグリゲータ回答のライブストリーミング: GPT-5 / Claude / Grok がどう考えたかを個別に読んでから、アグリゲータの最終回答がライブで stream される (#53793, #53855, #55625, #56101)
  • 完了契約 (completion contracts) による自己検証: /goal で「done」の条件を宣言すると、standing-goal ループがモデルの自己申告ではなく 証拠 に照らして完了を判定。プロジェクトの実際の checks を走らせて終了を判断する coding verification evidence ledger、pre_verify フック、verify-on-stop の1回限り v32 migration を同梱 (#50501, #52285, #55413, #53552)
  • /learn — 何でも再利用可能な skill に変換: ディレクトリ・URL・直前に実行した workflow を指定すると、Hermes が reusable skill に蒸留し CONTRIBUTING.md の基準に従って自動書き出し (#51506, #52372)
  • /journey — 学習タイムライン: CLI/TUI に蓄積された memories と skills の時系列表示を実装。デスクトップの memory graph（トップダウンの放射状タイムライン）と組み合わせて、エージェントの記憶が初めて可視化・編集可能に (#55555, #55859, #55226)
  • バックグラウンド fan-out: delegate_task が複数の subagents を background で並列起動し、全完了後に1つの統合ターンで結果を返す。チャットをブロックせず、fleet を並行稼働させられる (#49734)
  • デスクトップアプリの第一級 Projects: profile ごとの codebases サイドバー、coding rail、review pane、git worktree 管理、project → repo → lane モデル backed の agent 向き project ツール。散在する chat セッションから「coding cockpit」へ (#49037, #54385, #54517)
  • gateway の scale-to-zero + drain 協調: アイドル時の dormant 状態化、restart / migration / auto-update 前の quiesce、in-flight 会話を落とさない外部 drain 調整。ホスト/リレー運用が production-grade に (#52243, #52937, #54824)
  • /prompt で $EDITOR 上の長文プロンプト作成: 1行入力欄と格闘せず markdown で詳細 spec や大量 paste を編集して queue 投入 (#50509)
  • Google Vertex AI first-class provider: Vertex の OpenAI 互換 endpoint で Gemini を利用可能に。短命の OAuth2 access token を service-account JSON または ADC から自動 mint & refresh し、静的 API key 不要で稼働 (#56363)
  • より安価な自己改善: post-turn の学習フォークが auxiliary model にルーティングされ、会話全体を再再生せず context digest を処理し、cadence も適応化。本モデル価格の何分の一かで自己改善を維持 (#49252)

要点

  • 背景: Fable 5/Mythos 5 は 6/9 リリース。6/12 に Amazon 研究者の報告（Fable 5 の safety classifier を迂回して脆弱性を示せる件）を契機に輸出規制が発動し、全ユーザで利用停止に

  • Mythos 5: 6/26 に政府承認を得た米国内一部組織へ先行回復済み。Glasswing プログラム経由で段階拡大
  • 業界共通の jailbreak severity framework: Amazon・Microsoft・Google 等 Glasswing パートナーとともに「capability gain / breadth of capability gain / ease of weaponization / discoverability」の4軸で severity 評価する共通基盤を草案中
  • 政府との深化協調: 国家_SECURITY_関連で能力 front を進めるモデルの事前評価アクセス、safeguard 情報の速やかな共有、専任 Anthropic チーム・計算資源割当による共同研究、業界共通の voluntary security/evaluation standard の策定寄与を確約
  • 新 HackerOne プログラム: Fable 5 fog jailbreak 提出を受理（才）
