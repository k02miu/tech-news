🧠 Claude Code — v2.1.316

2026-10-31 10:06 JST 公開。Claude apps gateway の統制機能（共有予算・ポリシーのレイヤリング・Bedrock ガードレール連携）が厚くなり、あわせて ultrathink やサブエージェントの effort を制御する環境変数が追加されました。Opus 4.8 の fast mode は非推奨化が告知されています。

🔧 新機能・改善

  • ultrathink の無効化: CLAUDE_CODE_DISABLE_ULTRATHINK を追加。キーワードによる effort 引き上げを止められます。
  • group 共有予算（Claude apps gateway）: グループのメンバーで分け合う月次予算を、各メンバー固有の上限に上乗せして設定可能に。spend limits 管理 API の pooled_budget で指定します。
  • サブエージェントの effort 既定値: CLAUDE_CODE_SUBAGENT_EFFORT を追加。他に指定がない場合にサブエージェントが動く effort を、セッションからの継承ではなく明示的に設定できます。
  • ポリシーのレイヤリング: managed.policy_mode: layered を追加。開発者に一致するポリシーが（最初の1件だけではなく）すべて適用され、下位のポリシーに順にマージされます。
  • Bedrock ガードレール連携: Claude apps gateway の Bedrock upstream に guardrail.input_tagging を追加。Amazon Bedrock ガードレールのプロンプト攻撃フィルタが必要とする入力タグでプロンプトを包みます（all_messages_and_system ではシステムプロンプトも対象）。
  • ループした相互証明書の保持: CLAUDE_CODE_DISABLE_LOOPED_CROSS_CERT_DROP を追加。プライベート CA が相互に証明し合う証明書を必要とするサーバー向けに、その破棄を抑止します。
  • [VSCode]: チャットパネルから Claude apps gateway へサインイン可能に（ターミナル不要）。
  • [Cloud sessions]: MCP サーバーが求めるフォームを、気づかないうちにキャンセルされるのではなく入力／辞退できるフォームカードを追加。「Catching up…」表示により、切り戻したクラウド／Remote Control セッションのメッセージ同期中であることが分かります。
  • [Code Review]: アナリティクスページに severity 別の findings カード（期間合計、severity 積み上げの日次チャート、severity 別件数）を追加。

🐛 主な修正・挙動変更

  • Opus 4.8 の fast mode を非推奨化: 2026年10月30日付で非推奨、2026年11月30日に削除予定。削除後は Opus 4.8 の fast mode リクエストがエラーとなり、標準 Opus 4.8 へのフォールバックも行いません。速度優位を維持するには Opus 5.5 への移行が必要です。
  • auto mode のルール解釈: "$defaults" を含まない autoMode.allow リストが、スケジュールタスク向けプロンプトの組み込みルールを削除しなくなります。
  • サーバー管理設定（Team / Enterprise）: Anthropic API から取得した設定が承認プロンプトなしで適用され、検証に通らない保存済みコピーは拒否されるようになりました。
  • [VSCode]: ultrathink がターミナルと同様に xhigh effort でターンを実行し、チャットボックスでレインボー表示されるようになりました。
  • [Cloud sessions]: ネットワークシークレットを Enterprise メンバーが自分のクラウド環境で追加・削除可能に（従来は閲覧のみ）。
  • [Claude Tag]: Slack チャンネルの「Respond automatically」スイッチが、チャンネル設定ページおよび Claude Tag 管理設定で「How Claude participates」の選択肢に変更。
