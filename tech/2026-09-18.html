🧠 Claude Code — v2.1.275 / v2.1.274

対象期間内に v2.1.275（9月18日 07:42 JST 公開）と v2.1.274（9月17日 09:19 JST 公開）の2件がリリースされました。RSS フィード（code.claude.com/docs/en/changelog/rss.xml）の pubDate を全件照合した結果です。両バージョンとも VSCode 拡張・Claude Code on the web・Claude Tag（Slack 連携）・Code Review にわたる広範な修正を含みます。

🔧 新機能・改善（v2.1.275）

  • 送信キーの追加: 現在のターンを中断してキュー済みメッセージを一括送信する ctrl+enter（または ctrl+x ctrl+s）を追加。送信済み・キュー済みメッセージはモデルが受け取るまでグレー表示になります
  • Claude apps gateway のサインイン改善: サインイン中のアカウント名をゲートウェイが提示した場合に確認してから資格情報を保存し、/status にも表示。/logout はトークン失効を広告するゲートウェイ側のセッションも終了させます
  • claude.ai アカウントの skills / plugins を同期: claude.ai で有効化したスキルとプラグインがターミナルセッションにも同期されるように。syncClaudeAiSkills: false / syncClaudeAiPlugins: false でオプトアウト可能
  • /plugin install <plugin> --marketplace <source>: プラグイン導入前にマーケットプレイスの追加を提案する形式を追加
  • テレメトリ: 設定済みの otelHeadersHelper が失敗した際に起動時警告を出すようになり、テレメトリが無言で出力されないセッションに気付けます
  • プラグイン取得の堅牢化: npm ソースのプラグインは npm pack --ignore-scripts と完全性検証を伴って取得されるようになり、パッケージの install スクリプトが実行されなくなりました
  • アーティファクト／画像: タブアイコンを絵文字 favicon ではなく一単語で指定する方式に変更。貼り付け・添付画像は Desktop や VS Code を含めパーミッションプロンプトなしでファイルとして開ける場所に保存されます
  • [VSCode]: Memory ダイアログで保存済みメモリの参照・編集・削除に対応。提案差分タブに変更ごとの accept / reject ボタンを追加。エージェントマップの改善（稼働数バッジ、失敗時の赤表示、メインエージェントの固定表示）

🐛 主な修正（v2.1.275）

  • compaction / resume 後に復元されたメモリファイルの age 表記がリクエスト間で変わり、プロンプトキャッシュミスを起こしていた問題を修正
  • プラグイン・マーケットプレイスのメッセージやログ、claude plugin marketplace list が git / ssh / マーケットプレイス URL に含まれるパスワードやトークンを表示していた問題を修正
  • 壊れたトランスクリプト（不正な task-reminder や @-file 添付、不正なメッセージ content block）で --resume やセッション開始が失敗する問題を複数修正。/rewind のゼロ埋め・切り詰め復元も修正
  • 20MB 出力上限を超える検索で Grep / Glob / @-file サジェストがハングまたはメモリ枯渇する問題、および警告多発時に system ripgrep が「該当なし」と誤報告する問題を修正
  • ネットワークゲートウェイが API エラー応答を書き換える環境で、毎ターン API Error: 400 になる問題を修正
  • Linux のサンドボックス Bash が zsh シェル時に失敗コマンドでも終了コード 0 を返す問題、hooks/ や config/ 名のプロジェクトディレクトリへ書き込めない問題を修正
  • [VSCode]: 高速タイプ時やキー長押し時に fullscreen セッションが「unrecoverable interface error」で終了する問題、巨大なファイル差分を遡る際のフリーズ／ブランク、応答ストリーミング中に上へスクロールしても最下部へ引き戻される問題（claudeCode.scrollToBottomOnSend 設定も追加）などを修正
  • [Claude Code on the web]: 非常に長い許可ドメインリストを持つクラウド環境で保存は成功するものの全セッション起動が失敗する問題を、保存時にエラーとして弾く方式に変更

  • メモリ逼迫の警告: メモリ使用量が危険域に達した際の可視警告と、安全に解放／再起動する手順を表示

🐋 Orca — v1.4.205

対象期間内に v1.4.205（9月17日 13:59 JST 公開）がリリースされました。ネイティブチャットのメッセージレール追加や、ワークツリー削除時の安全性確保、ターミナルハンドルの PTY 再生成をまたぐ保持、Codex 使用量スキャンの大幅な高速化などが含まれます。

🔧 主な内容

  • エージェント／チャット: プロンプト間をジャンプするメッセージレールをネイティブチャットに追加。再開したトランスクリプトを末尾に固定し、メッセージ増加中も切り離したリーダーの位置を保持。保留中のプロンプトのキャンセルを正確化。OMP の会話が保存済み名でセッション履歴から再開可能に
  • セッション／フック: タイムアウトしたフックが実際にプロセスツリーを終了するよう修正。エージェント状態の取り込みを単一の admission point に集約（レガシー経路を分離）
  • ワークスペース／エディタ: アーカイブフックが失敗した場合はワークツリー削除をブロックするように変更（従来は削除を続行）。prunable な git-file 登録状態でもワークツリー登録が生き残るよう修正。コードブロックにコピーボタンを追加。Tiptap を Markdown 互換ガード付きで更新
  • ソース管理: stage / unstage / discard の失敗をリトライ手段付きで表面化。Git 起動時の ENOENT を「バイナリ不在」と「cwd 不在」で区別して報告
  • ターミナル／リモート: ペインのハイドレーション前にターミナル名変更が失われる問題、PTY インカネーション回転をまたぐハンドル保持、PTY 子プロセス検査で「検証不能」を推測せず保持する修正。リレー障害を取得フェーズと実行フェーズで切り分けて診断可能に
  • 性能: Codex 使用量スキャンで帰属解決をスキャンごとに1回とし、成長したロールアウトは最後に解析したバイト位置から再開。大規模なコールドスキャンが数分から1分未満に短縮（ワーカースレッド移行は後続リリース）
