🧠 Claude Code — v2.1.282

対象期間内（2026-09-25 03:46 JST 公開）に v2.1.282 がリリースされました。今回は マネージド設定の適用漏れとセッション継続時の拡張思考（extended thinking）消失の修正が目玉で、加えて vim モードの挙動修正が非常に多くなっています。ターミナル描画まわりの細かな修正も多数含まれます。

🔧 新機能・改善

  • maxProseWidth 設定を追加: ワイドなターミナルで Claude の文章部分の幅を制限しつつ、テーブルとコードブロックは全幅を維持できるようになりました。
  • テレメトリ設定の可視化: プロジェクトの設定ファイル内で無視された、あるいはテレメトリを無効化していたテレメトリ系環境変数を、起動時のお知らせ・/status・claude doctor が列挙するようになりました。
  • Chrome 連携とマネージド MCP の共存: 新しいマネージド設定 allowClaudeInChromeWithManagedMcp により、排他的な managed-mcp.json と併用して claude --chrome を実行できます。Chrome がブロックされた際のエラーメッセージもこの設定名を示します。
  • Claude apps gateway の可用性向上: store.readiness_grace_seconds が追加され、Postgres のフェイルオーバーのような短時間の障害中も /readyz が ready を返し続けられます。
  • 非常に大きなセッションの復帰が高速化: compact を一度も実行していない巨大セッションを含め、再開までの時間が短縮されました。
  • UI 改善: フルスクリーン時の /feedback 下書き一覧にスクロールバーが付き、/artifacts はタイトルが 1 列に揃い、詳細が途中で切られずに表示され、PgUp/PgDn・Home/End・マウスホイール・クリックに対応しました。権限プロンプトの特殊 Unicode 表示、Windows での transcript 読み取り失敗時のエラーメッセージ、Claude Desktop の未知モデルエラーの案内も改善されています。

🐛 主な修正

  • 「Invalid data in redacted_thinking block」で全ターン失敗する問題を修正: 該当セッションの thinking ブロックを破棄して 1 回リトライするようになりました。
  • セッション継続・復帰時の拡張思考の消失を修正: --continue／--resume で過去メッセージが別の形で再送され推論が失われる問題、過去の組み込みツールを含まない --tools 指定で再開した際に過去の拡張思考が失われる問題が解消されました。Claude の作業中に /model・/rename・/artifacts などの即時スラッシュコマンドを使うと拡張思考が落ちる問題も含まれます。
  • 要約リクエストが拒否された際の compaction 失敗を修正: フォールバックモデルでリトライするようになりました。
  • マネージド設定の適用漏れを修正: disableClaudeAiConnectors などの真偽値ロックキーに打ち間違いがあるとロック自体が無視されていた問題、ネストした値が 1 つ不正だと permissions・autoMode・worktree・attribution ブロック全体が無視されていた問題、リポジトリ／ユーザー／--add-dir のスキルやコマンドが allowed-tools で自身のツールを事前承認できてしまう問題が修正されました。
  • 認証・ログインまわりを修正: 別プロセスが更新中に終了・強制終了された後、最大 1 分間「another Claude Code process is refreshing it」で失敗する問題、複数の VS Code ウィンドウでサインイン更新中に起動したセッションが組織ポリシー取得を再試行しない問題が修正されました。
  • Web 検索結果を含む履歴で全リクエストが 400 になる問題を修正: API が復号できない web search 結果が会話履歴に含まれるケース（サードパーティ gateway 経由の回答など）が対象です。
  • シンボリックリンク経由の設定読み込みを修正: リポジトリ内シンボリックリンクから .. や /.vol 形式のカーネルパスで macOS の /Network に到達して CLAUDE.md やルールが読まれる問題、macOS の /home へのルールリンクが列挙される問題が修正されました。
  • vim モードを多数修正: 空行への >>、行長を超えるカウント付き r、2J が 1 行多く連結する問題、最終行での 2dd／2>>、dd／dj／dG 後のカーソル位置、絵文字後の Esc、. の前のカウント無視、行折り返し時の p／o／J などの対象行ずれ、履歴から呼び戻したプロンプトでカーソルが行末を越える問題が解消されました。
  • そのほか: ターミナルの bracketed paste モードがリセットされた後に複数行貼り付けが 1 行ずつ送信される問題、フルスクリーン起動時に最初のフレーム前に空白画面が点滅する問題、CJK 文字や絵文字が折り返した際に diff の最終列に文字が残る問題、/skills 検索ボックスで / 直後のキー入力が一覧移動になる問題、Bash／PowerShell がディスククォータ超過を「Exit code 1」に隠す問題、/install-github-app をキャンセルしてもブランチ push とシークレット保存が続行される問題などが修正されました。
  • VSCode / Cloud sessions / Claude Tag: 長い応答がストリームに追いつかなくなる問題、Remote Control セッションが一覧から開けない問題、Claude GitHub App の状態表示、別 owner のリポジトリを実行中クラウドセッションへ追加、Slack 上のカード表示幅やコスト合計が過大になる問題などが修正されました。

⚙️ 動作変更

  • テレメトリを無効にした state で直接 Anthropic API に接続している場合、auto モードはサーバーサイド分類器を既定で使用します（CLAUDE_CODE_AUTO_MODE_SERVER=0 でオプトアウト）。
  • Skill(anthropic-skills:*)／Skill(claude-ai:*) の許可ルールは、claude.ai から同期されたスキルのみを対象とし、同名のプラグインやその他のスキルは対象外になりました。同ネームスペースのスキルフォルダ・コマンドは読み込まれなくなり、同名の MCP サーバーはスキル・プロンプトを列挙しなくなります（ツールは動作します）。
  • プロジェクト／ローカル設定は、テレメトリのエクスポートや内容キャプチャを有効化する OpenTelemetry 変数（CLAUDE_CODE_ENABLE_TELEMETRY、OTEL_LOG_* など）を無視するようになりました。

🐋 Orca — v1.4.210

対象期間内（2026-09-24 14:25 JST 公開）に v1.4.210 がリリースされました。チャットの完了・失敗時の挙動整理、ターミナルのデーモン生存性、使用量レポートの対応モデル拡大が中心です。

🔧 新機能・改善

  • 構造化チャットの状態表示: 完了したターンは回答だけに折りたたまれ、エージェントが失敗を報告した時にはターンがハングせず終了します。構造化チャットが完了すると未読インジケータが点灯し、再起動リカバリがステータスバーから利用できるようになりました。
  • エージェント起動コンテキストの整備: ホスト側で導出できない起動入力を起動時に受け渡す仕組みが入り、ターミナル起動が作成したペインを報告するようになりました。既定エージェントは共通ランチャー経由で起動されます。
  • Antigravity を supervised worker として実行可能になりました。
  • 使用量レポート: Fable アカウントの Claude 使用量ポーリングがライブセッション中も継続されるようになり、GPT-6 Astra のコスト計算に対応しました。また Codex のコスト合計が特定モデルを除外している場合はその旨を明示するようになりました。
  • ターミナル: テーマ選択が Ghostty の色設定を上書きできるようになり、macOS では Orca のターミナルサービスがフォルダを読めない場合に修復手順を案内します。レイテンシ計測は present 済みの CI フレーム基準になりました。
  • エディタ／ワークスペース: 巨大な成果物一覧と競合一覧を仮想化し、検索クエリ変更時の古い一覧表示を修正しました。アップデータは GitHub トークンを送信し、リリースピッカーのビルド一覧をキャッシュします。

🐛 主な修正

  • ターミナルデーモンを専用の systemd scope に分離し、サービス再起動で稼働中の全 PTY が失われる問題を解消しました。シャットダウン時の子プロセス reap、Linux で所有プロセス終了時に孤児プロセスを解放する処理も追加されています。
  • リモート／信頼性: WSL ゲストが OpenCode の agent バリアントを維持するようになり、再作成された SSH ターゲットは generation floor を保ちます。relay wave の失敗テンプレートはバックエンドサービスに影響せず掃除されます。
  • サイドバー: 構造化チャットを持つワークスペースが「スリープ中」と表示される問題を修正しました。
  • サブエージェントの帰属: サブエージェントの出力が、それを起動したエージェントの発言として扱われる問題を修正しました。
