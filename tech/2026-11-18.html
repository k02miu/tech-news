🧠 Claude Code — v2.1.327

2026-11-18 08:22 JST に v2.1.327 が公開されました。MCP のトークン取り扱い改善、/status による設定破損の可視化、権限・サンドボックス判定の厳格化が中心のリリースです。

🔧 新機能・改善

  • トークンをコマンドラインに残さない MCP 登録: claude mcp add-json <name> - でサーバーの JSON を標準入力から読み取れるようになりました（Claude Code セッション内では利用不可）。
  • 設定破損の一覧表示: /status に、壊れた agent・skill・command・output style ファイル、キーバインドのエラー、利用できないサンドボックス、無視された権限設定、決して一致しないフックマッチャーが表示されるようになりました。
  • 設定の上書きを明示: /config で他の設定がその行を上書きしている場合に注記。
  • セッション復元時の案内: 再開したセッションで以前のメッセージを読み込めない場合に、その旨を1行表示。
  • /install-github-app: リポジトリを変更する前に確認を求めるようになりました。
  • 課金グループ名の指定: attributionProject 設定でセッションの課金グループを命名可能（admin.billing_group_tag を設定する Claude apps ゲートウェイ向け）。
  • ゲートウェイ連携: x-claude-code-managed-settings-checksum をヒントヘッダーに追加。CLAUDE_CODE_GATEWAY_HINT_HEADERS=1 の管理設定で送信されます。
  • 表示名: 非フルスクリーンのレンダラー名として /tui classic を追加（/tui default も引き続き有効）。
  • [VSCode]: エクスプローラーの右クリックメニューに「Claude Code: Add to Chat」を追加し、選択したファイル・フォルダをチャットで @ メンションできます。

🐛 主な修正・挙動変更

  • 権限・パスの厳格化: 一部のシンボリックリンクを拒否し、「作業ディレクトリ内」と見なす範囲も変更。これにより一部のパスで権限確認が発生します。
  • blockReadsOutsideWorkingDirectories: bypass／auto モードでより多くの Bash コマンドについて確認するよう変更し、auto モードでは一部を拒否。
  • auto モードの許可ルール: Bash(pnpm dlx *) のように任意のパッケージを実行する許可ルールをより多く無視するよう変更。判定は安全性チェックが担当します。
  • 長すぎる変数展開: 変数が非常に長いテキストに展開される Bash コマンドを拒否し、短い値かファイルの使用を促すメッセージを表示。
  • ExitWorktree: 未保存の作業を含む可能性がある worktree を削除する前に確認するよう変更（don't-ask モードや応答者がいない場合は拒否）。
  • claude mcp add --scope project: .mcp.json が mcpServers キーなしでトップレベルにサーバーを列挙している場合、上書きせず停止するよう変更。
  • 権限プロンプトのカーソル: 矢印キーは「No」で折り返さず停止するようになり、最後の選択肢を超える番号は「No」に移動。
  • PowerShell ツール: 対象を名指しするルールがあっても、一部コマンドで事前確認を求めるよう変更。
  • サブエージェント: モデル未指定で起動したサブエージェントは、/model 後も再開時に開始時のモデルを維持。再開されたサブエージェントはセッションの権限設定に従います。
  • トークン削減: Amazon Bedrock・Google Vertex AI・Microsoft Foundry のターミナルセッションで、サブエージェントの進捗要約を会話全体ではなく短いメモから生成するよう変更。
  • Artifact ツール: 設定で Artifacts をオフにした場合、実行中のセッションでも呼び出しを拒否するよう変更。
  • -p（非対話）モード: 最初のリクエスト前に実行する git コマンドを削減。
  • その他: アカウント変更後に一部の事前起動バックグラウンドセッションを破棄、/sandbox と /config の値リストをスクリーンリーダーモード以外では番号なし表示に変更。

🐙 OpenClaw — v2026.11.5

2026-11-17 19:47 JST に v2026.11.5 が公開されました。Gateway 再起動をまたぐ会話の保全、更新失敗時のロールバック、Telegram のインタラクティブウィジェットが主な柱です。

🔧 新機能・改善

  • 再起動に強い会話: キュー済みメッセージ、送信権限、最終的なチャット書き込みが Gateway の再起動をまたいで保持されます。
  • 安全なアップデート: Doctor または Gateway の起動に失敗した場合、有効化済みのアップデートをロールバック。復元された npm パッケージは非 root サービスからも読める状態を維持します。
  • Telegram ウィジェット: Telegram のメッセージ内でインタラクティブウィジェットを描画可能に（プライベートチャットのトピックを含む）。
  • メモリ索引の復旧: 大規模なメモリ索引の再構築が確実に完了し、Gateway がバッチ上限エラーを切り詰めた場合も埋め込み索引が復旧します。
  • モデルフォールバック: プライマリとして設定されたアカウントが Claude CLI へのフォールバックを妨げなくなり、OpenAI セッションはコンパクション項目の競合から復旧します。
  • デバイスフォルダ: 既定ランタイムでも既存のデバイスフォルダを選択可能に。
  • コンテンツ境界: バイナリ添付が文字化けしたプロンプト本文にならず、認証済みブラウザの CDP URL がツール結果に残らなくなりました。
  • 業務セッションとセキュリティプリセット: personal モードのメッセージは対応可能な作業を誘導するか静かにキューイング。personal／corporate のセキュリティプリセットが一貫した既定値を提供します（明示設定と必須のアクセス・承認制限は引き続き優先）。
  • コンパクション: maxSummaryChars で要約の文字数上限を制御できます。

🐛 主な修正・互換性注意

  • 破壊的変更: サードパーティ製ハーネスは、セッションキー付きのアクティブランをホストの runAttempt コールバック内で登録し、返されたクリーンアップ関数を保持する必要があります。プラグインの RPC ハンドラーは chatAbortControllers／chatQueuedTurns を、認可済みの Gateway メソッドディスパッチに置き換える必要があります。start-owner の観測は expiresAtMs ではなく startDeadlineAtMs を使用します。
  • 認可: キュー済みの自動化実行は開始前に owner 専用メモリへのアクセスを再確認し、子の失敗結果も親ターン終了後に配信可能なまま保持されます。
  • Gateway 復旧・リロード: ワークスペース準備後に中断されたターンを再開し、設定更新がファイルウォッチャーの競合でハングしなくなりました。
  • cron: スケジュール済みアカウント選択やリトライ期限を保持し、遅いスケジューラ起床でもジョブを黙って落とさないよう修正。設定のホットリロードが実行中のジョブを中断しなくなりました。
  • Telegram: 進行状況ストリームモードでの ACP 返信を復旧し、承認がプライベート／フォーラムトピック内に留まるよう修正。
  • チャネル: キャプション付き Feishu メディアの配信、Matrix・Mattermost での Unicode ディレクトリ照合の正規化を修正。
  • iOS 音声: 画面ロック中も Talk が動作し続け、音声権限の「許可」操作でアプリがクラッシュしないよう修正。

🐋 Orca — v1.4.262

2026-11-18 08:20 JST に v1.4.262 が公開されました。多数のチャットを開いたままのメモリ使用量と切り替えコストの削減、Git blame の常設表示、エージェント設定の一本化が中心です。

🔧 新機能・改善

  • 多数のチャットでの作業: macOS と Linux で Chat UI がより軽量なヘルパーを使用。非表示のチャットビューは更新を止めつつ、下書き・閲覧位置・エディタ状態を保持し、エージェントは作業を継続します。
  • ディスク容量の回収: 設定 → Workspace Cleanup で、削除済みワークスペースの Orca・Claude Code・Codex のチャットを削除可能。既定はオフで、有効化時には確認を求めます（削除したチャットは復元不可）。
  • ターミナルのカレントディレクトリ保持: ペインが再起動をまたいで最後に移動したディレクトリを記憶（フォルダワークスペースを含む）。Windows ではビジー状態のペインに戻った際の余計な文字混入も修正。
  • Git blame: Git blame ステータス項目にカーソル行の作者と日付を表示。リポジトリワークスペースではクリックでコミットを開け、設定 → Editor の「Inline git blame」でコード横に注釈を表示できます。
  • アカウント切り替えの明確化: 保存済みの Claude／Codex アカウントに名前を付け、最後に観測したプランを確認可能。Restart または Always restart を選ぶと、ビジーな Claude ターミナルセッションは現在の作業完了を待たずに選択アカウントで再開します。
  • エージェント設定を1枚のカードに: エージェント・モデル・対応する effort／Fast オプションをまとめて選択し、「Open as chat」「Open as terminal」で起動。Default effort ではエージェント自身にレベルを選ばせられます。
  • 通知の制御: ワークスペースを右クリックして通知をミュートしつつ未読ドットは維持。スリープ状態のワークスペースは再起動後もスリープを保ちます。
  • 言語とプラグイン: 設定またはオンボーディングでコミュニティ翻訳を発見可能。プラグイン更新のレビューでは追加されるアクセス権が明示され、承認をまとめられます。
  • リモートファイルの保存: リモートファイルのリンクで「Download…」を選び、別アプリを開かずに保存できます。Windows は WSL ディストリビューションにマップされたドライブレター上のプロジェクトフォルダも認識します。
  • Codex のブロック解除: 自動レビューで拒否されたアクションについてチャットが理由を説明し、そのアクションに対する「Approve once」を提示します。

⚠️ 互換性・アップグレード注意

  • Codex 履歴の共有: 共有を有効にすると、次回起動前にアカウントが単一の会話ストアへ移行します。初回起動が遅くなる場合があり、ビジーなアカウントは後で移行されます。
  • Windows ターミナル: 余計な文字混入の修正を反映するため、既存のターミナルを閉じて開き直してください。
  • リポジトリのセットアップ手順: 以前の orca.yaml 承認は、そのリポジトリのセットアップコマンドの将来バージョンに対する信頼として扱われます。

  • Amazon Bedrock で OpenAI GPT-6.2 Astra / GPT-6.2 Sol が一般提供: Astra は高度な推論・判断と Ultrafast モード、Sol は定型的なコーディングやエージェント作業の速度とコスト効率を重視した構成です。
