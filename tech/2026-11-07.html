🧠 Claude Code — v2.1.319

2026-11-07 03:06 JST 公開。MCP タスクのバックグラウンド実行、権限プロンプトを待たずに拒否する設定、Claude API のレイテンシ最適化コマンドが加わりました。あわせて auto モードのサーバー側検証や Monitor のルール適用など、統制まわりの挙動が多数変更されています。

🔧 新機能・改善

  • MCP タスクのバックグラウンド実行（ターミナル）: MCP サーバーがツール呼び出しをタスクとして実行する場合、Claude Code は即座にバックグラウンドへ移し、完了時に Claude へ結果を通知します。
  • CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND: 上記の即時バックグラウンド化を止め、ツール呼び出しの中で完了を待たせる環境変数です。
  • permissions.denyInsteadOfPrompting: 権限プロンプト待ちになるツール呼び出しを「拒否してターンを継続」に切り替える設定。ターミナルセッション、サブエージェント、teammates に適用されます。
  • /claude-api latency-optimize: Claude API 呼び出しのどこで待たされているかを特定し、評価セットに対して高速な設定を試せる新コマンドです。
  • CLAUDE_CODE_DISABLE_FEATURE_FLAGS: テレメトリを止めずにフィーチャーフラグ取得のみを停止し、全フラグを組み込み既定値で動かします。
  • /usage の支出表示: Claude apps gateway 経由で支出上限のない開発者に対し、当日・今週・今月の支出を表示します（同バージョン以降のゲートウェイが対象）。
  • Claude apps gateway の運用機能: 複数グループ所属時の pooled 予算の優先順位（admin.pooled_conflict_rule / admin.pooled_priority_order）、サインイン画面などに出す login_notice、JSON 形式の運用ログ（CLAUDE_GATEWAY_LOG_FORMAT=json）、起動時警告の拡充が追加されました。
  • サインインの可視化: claude.ai のログインが切れて ant auth login のサインインに切り替わり、Claude Console 組織に課金される場合に警告し、起動時に課金先組織名を表示します。
  • /tasks の「Earlier in this session」: 終了済みサブエージェントを一覧から再オープンし、メッセージを送れる行が追加されました。一覧から外れた後や再起動後でも追跡できます。
  • クラウドセッションの /loop: タイマーがコンテナとともに停止する旨の注意と、存続するループの提案が確認ダイアログに表示されます。

🔄 主な変更

  • auto モードのサーバー側チェック: テレメトリやフィーチャーフラグが無効（LLM ゲートウェイ配下を含む）の場合、サーバーが検証できない呼び出しは確認または拒否となり、組み込み分類器へのフォールバックは行われません。CLAUDE_CODE_AUTO_MODE_SERVER=0 で従来動作を維持できます（Bedrock / Vertex / Foundry は変更なし）。
  • MCP タスクの適用範囲拡大: フィーチャーフラグ取得なしでもターミナルで動作するようになりました。CLAUDE_CODE_DISABLE_MCP_TASKS=1 で無効化できます。
  • Monitor の WebSocket 監視: 全 Bash コマンドに対してルールを適用。deny は拒否、ask ルール下では Monitor の allow・bypass モード・auto モードでもプロンプトを省略しなくなりました。
  • Bash ツールの権限確認: フラグ付きの which 実行前に、参照・表示系の範囲外であれば許可を求めるようになりました。
  • ネストしたスキル読み込み: Bash サンドボックス有効時、開始フォルダより下の .claude/skills は、そこで起動するか /cd した場合のみ読み込まれます。
  • /loop（セルフペース）: 再スケジュールなしでターンが終わった時点で終了するようになりました（CLAUDE_CODE_LOOP_KEEPALIVE=1 で従来動作）。
  • PostToolUse フック: 新しいメッセージでターンが中断された後に完了したツール呼び出しでも、最大10秒の猶予で実行されるようになりました。
  • サブエージェント停止時の挙動: セーフガードで停止した場合、Claude 自身が作業を代行するのではなく、プロンプトを絞って再試行するか利用者に伝えるよう指示されます。
  • 削除・廃止: Claude in Chrome 組み込みツールから shortcuts_list / shortcuts_execute が削除されました。また自己ホストランナーではセッション終了時のデバッグログのアップロードが廃止されています。
  • [VSCode] / [Code Review]: Claude の返信内のサインイン・コネクタ・API アドレスへのリンクはブラウザで開かずテキスト表示に。Code Review で GitHub 組織のリンクを外すと「All repositories」設定も無効化されます。

なお本バージョンの RSS エントリには Fixed（修正）セクションは含まれていません。

🐋 Orca — v1.4.251

2026-11-06 15:31 JST 公開。スマホ側チャットの大幅な機能拡張、任意の選択範囲をチャットへ送る「Add to chat」、再起動後のチャット復元、ワーカーの入れ子起動が中心です。あわせてターミナル再接続の安定化と起動・描画の性能改善が入っています。

🔧 新機能・改善

  • スマホのチャット強化: 過去メッセージへの巻き戻し、停止した応答の継続、エージェントの計画をコンポーザー上部に固定表示、画像と長文の貼り付け、チャットのゴール設定・管理、コンテキスト使用量リングの表示、未送信ドラフトのアプリ再起動をまたぐ保持に対応しました。
  • Add anything to chat: ファイルの選択範囲、Markdown プレビュー、ターミナルの選択範囲をワークスペース内の任意のエージェントへ送信、あるいはそれを起点に新規エージェントを起動できます。
  • 再起動後のチャット復元: 新規インストールでは Orca の終了・更新後に作業中チャットが自動で復元されます。
  • ワーカーがワーカーを起動: 入れ子ワーカーが既定で許可され（深さの既定は4）、終了したワーカーはコーディネーターへメッセージを送り続けられ、停止時は配下のヘルパーも停止します。
  • 日常操作の高速化: 起動時のログインシェル取得を1回に削減、ソース管理とタブバーの重複処理を削減、長いチャットの応答性を改善しました。
  • ターミナルの安定化: デーモン再接続後にターミナルが再アタッチされ、メインプロセスの一時停止をまたいでも接続を維持。新しい GPU キャンバスが空白で点滅しなくなりました。
  • プロジェクト整理: プロジェクトの一括折りたたみ／展開、コンテキストメニューからの子 worktree 作成、フォルダプロジェクトグループの更新に対応しました。

⚠️ 互換性・アップグレード注意

  • 入れ子ワーカーの深さ: 既定が4になり、1 に設定していた既存プロファイルはアップグレード時に4へ移行します（設定画面で戻せます）。
  • 再起動後の復元: 既定で有効なのは新規インストールのみ。既存ユーザーの保存済み選択は維持されます。
  • Claude の権限状態: Claude 自身が要求を終了した際の「needs permission」解除には Claude 2.1.118 以降が必要です。
  • Chat UI メニュー: 「Fork Agent Session…」が Chat UI のメニューから外れました（ターミナル側には残ります）。
